# v1.6.8 受入・検証記録

検証日: 2026-09-27。現行仕様とv1.6.8確定要件を実装目標にした。サブエージェントは使用していない。Doc/archiveを根拠として読まず、引き継いだv1.6.7要件の移動を内容変更なしでコミットする。

## 実装した内容

- 到着人数を10〜20＋floor(max(0,turn−1)/2)人へ変更。未管理支線にも同じ式を適用し、現在・次回予定の公開範囲を追加した。
- 待機中だけの過密基準を60人へ分離。審査定員20、移設跡地、通過方針、予測と実抽選を同期した。
- 有刺鉄線は新設・既存それぞれ最大2隣接。閉じた6壁の輪を許可し、必要な視界を先に検証する。全9種ゾンビの移動経路を最少ヘックス数へ変更し、目標選定と実際の地形MP消費を維持した。
- 通常プレイ・公開リプレイ・AIリアルタイムに、実際の公開移動順と差分を使う演出を追加。スキップ、停止、シーク、連打、古いコールバックの取消を共通化した。Coreは待機せず確定結果を返す。
- 日本語の9種の敵名、用語、ヘルプ、性能値、凡例を同期。壁詳細の旧放射方向図も新しい隣接数の図へ差し替えた。機動隊ゾンビは全生成元でHP75。簡易農場の固定上限なしを維持する。
- 移設の旧ID拒否に再照会情報を追加。previewで旧地点の4人口プールの全量残留を示す。read-onlyの常駐statusと、公開情報だけによる移動先接触リスクを追加した。
- Rules/State/Config18、Save25、Agent/Observation/Bridge23、Artifact22、Session/Checkpoint19、PlayTurn1.3、AiSession1.4。旧ゲーム継続は非破壊拒否。v1.6.7公開ZIPは記録されたHP60等を保持して観戦できる。

## status性能

[測定値と環境](v168-status.json)。実Coreで生成した51×51の履歴を用い、旧版と新版を交互に各3プロセスで測定した。各プロセス内で初回常駐取得1回、継続取得3回も測定した。値はstatus呼出本体の時間で、Node起動・module評価は含まない。OSのファイルキャッシュは消去していない。

| 状態 | 旧単発 中央値 / 最大 | 新単発 中央値 / 最大 | 新常駐初回 中央値 / 最大 | 新継続 中央値 / 最大 |
| --- | --- | --- | --- | --- |
| T1 / revision0 | 2,436 / 2,522ms | 2,037 / 2,134ms | 2,333 / 2,366ms | 48 / 51ms |
| T50 / revision588 | 8,581 / 8,621ms | 4,114 / 4,536ms | 4,423 / 4,633ms | 47 / 51ms |
| T84 / revision996 | 11,205 / 11,225ms | 5,100 / 5,205ms | 5,441 / 5,457ms | 55 / 66ms |

長期単発の中央値を**54.48%短縮**し、継続取得の中央値も1秒以内。T84単発の読込量中央値は10,782,938→7,272,951 bytes、gzip展開量は84,321,022→41,694,838 bytes。

CPUプロファイルで公開差分の全体複製・正規化と、履歴ファイルの重複パス検査が支配的と確認した。1回のload内だけの検証済み展開キャッシュ、変更のない公開JSON部分の共有、上限付き正規化文字列再利用、重複検査の整理で短縮した。全差分の再構成hashと履歴チェーン、ファイルの整合性・パス境界を検証し続ける。継続時はActive世代が変わればキャッシュを破棄して再検証する。

再現用: `scripts/v168-status-benchmark.mjs`。長期性能用は7初期部隊の移動力1、敵・到着・施設期限を遠いターンへ置いた専用Configである。各ターン11回の方針変更とEndTurnを実行し、架空のDecisionを注入していない。標準難度の戦績とは区別する。
