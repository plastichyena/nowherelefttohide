## 1. 位置付けと範囲

### 1.1 目的

スマートフォン縦画面（390×844 CSS px基準）で、**盤面を広く使い、判断に必要な情報だけを常に見せる**。現行UIは盤面以外の帯と詳細が多く、盤面が画面の約3割しかない。

### 1.2 変更するもの・しないもの（UIトラック）

v1.7.1は2つのトラックで構成する。**UIトラック**（§5.1〜5.6）と**不具合修正トラック**（§5.7）。本節はUIトラックの範囲である。

- **変更する**: 人間向けUI（`src/ui/`、`src/styles.css`）の構成・表示・選択操作。
- **変更しない**: ゲームルール、Core（`src/core/`）、GameState、Save形式、Replay、Agent API、Observation、Bridge、Session、WebMCP。UI専用の状態（選択・シート・アコーディオン）はController内だけに置き、GameState・Save・Replay・Agent APIへ含めない。
- UIトラックの作業中に`src/core/`、`src/agent/`、`src/session/`、`src/persistence/`の変更が必要になったら、**着手せず根拠と案を親へ返す**。不具合修正トラックの変更は§5.7に従う。

### 1.3 ユーザーが採用した方針

- 同じヘックスに複数の対象があるときの選択は、「作戦図／内政」の**モード切替で優先を変える方式をやめ、同じヘックスの再タップで対象を順送りにする方式（B案）**にする。
- 「内政」タブは、未選択時の概況（人口・支線・イベント・予測・建設）を見る画面にする。
- 常時表示は判断に必要なものだけにする。**0・未開始・正常は描かず、異常のときだけ出す**。
- 資源の5アコーディオン（食料・民需・軍需・燃料・電力）の仕様と、盤面上のユニット操作メニュー（移動／攻撃／待機／×）と確認UI（×／✓）は維持する。

## 4. 設計原則

- **P1 常時表示は判断に使う数字だけ**。上部は最大3段、盤面より上の合計は140 CSS px以下を目標にする。
- **P2 例外優先**。正常値（0、未開始、供給内、稼働）はチップ1個か非表示。異常は色と形（文字・記号）の両方で示す。色だけに頼らない。
- **P3 同じ情報は1か所**。重複させない。
- **P4 段ごとに中身を変える**。折りたたみ=名前と状態、標準=要点と主要操作（スクロールなし）、展開=詳細。
- **P5 説明文は画面に混ぜない**。ルール説明（tip/muted）は常設ヘルプに任せ、パネルから外す。
- **P6 ID・内部キーを見せない**。

## 5. 要件

### 5.1 上部の構成（U）

**U-1 HUD（1段、約44 CSS px）**: `ターン番号 · フェーズ` | `人口 N` | `⋯`メニュー。ゲーム名を表示しない（タイトル画面とヘルプには残す）。人口チップは44px以上のボタンとし、タップで人口内訳（市民・労働者・部隊・待機・審査・合格・感染・健常民間人口）を盤面上に重ねて表示する。内訳の内容と値は現行の「人口の所在地」と同じ（`populationLocationTotals`）。

**U-2 資源（1段）**: 5アコーディオン（食料・民需・軍需・燃料・電力 需要/供給）を維持する。展開パネルの内容・開閉規則は現行仕様5.1のとおり。**Core Forecastで不足がある資源は、ボタン全体を警告色（背景と枠）にし、文字`!`も維持する**。

**U-3 状況チップ（1段、条件付き）**: 次を横1行に並べる。幅が足りない場合は警告チップを省略記号で切り詰め、横スクロールや折返しをしない。いずれも44px以上のボタン。

- **Horde（常時）**: 現行のHorde警告カードの見出しと進行状態を、1個のチップへ置き換える。例: `襲撃 T10・あと9` / `襲撃警告 2方向・あと2` / `最終襲撃`。タップで現行のHorde詳細（次Waveの番号・Spawn Turn・残り・方向数・方向・混成・Wave種別・基礎/確定/出現済/Pending人数）を盤面上に重ねて開閉する。初期は閉じる。「最終襲撃発生ターン」はこの詳細へ移す。Horde警告の色分け（none/periodic/final）は維持する。
- **感染（感染者が1以上のときだけ）**: `感染 N`。赤。タップで人口内訳を開く（U-1と同じ）。
- **警告（Crisis／戦略警告が1件以上のときだけ）**: 最優先1件の短い名詞句と残件数。例: `⚠ 発電所 停電予測 +1`。Criticalは赤、Warningは琥珀、Advisoryは青。タップで現行の`open-crisis`と同じ動作（シートを展開し、概況の危機セクションを開く）。文章を長く出さず、対象の名前と事象を短く出す。
- **勝利進捗（最終襲撃が始まってからだけ）**: 条件は`finalHordeStatus !== 'notStarted'`、または最終の待機数・盤面数のどちらかが0より大きいとき。`最終 待機N / 盤面M`の1チップ。最終襲撃前は表示しない。
- **保存失敗（`saveStatus === 'failed'`のときだけ）**: 赤チップ`保存失敗`。タップで手動保存を開く。

**U-4 保存状態**: 通常時の「保存済み・最終保存ターン」の行を廃止する。状態文字列は`⋯`メニュー内に表示する（`saveStatusLabel()`を再利用）。保存中・未保存の変更は、メニューのボタンに小さな点で示す。

**U-5 `⋯`メニュー**: ヘルプ、手動保存、言語切替、保存状態の表示。現行のUIに既にある操作だけを入れる（新機能は足さない）。盤面アイコン凡例はヘルプ内の現行入口を維持する。

**U-6 補給オーバーレイ切替**: 上部HUDから外し、盤面の右上隅に44px以上のトグルボタン（`aria-pressed`）として置く。`unit-mode-indicator`（盤面上端中央）・ユニットメニュー・Stack Picker（§5.2）と重ならない。検問所選択・建設などでの自動表示は現行どおり。

**U-7 未使用コードの整理（任意）**: `strategic-critical-strip`は、CSSと`updateHud`の更新処理が残っているがHTMLには出力されていない。参照するテストが無いことを確認できた場合に限り、除去してよい。

### 5.2 選択モデル（S、B案）

**S-1 対象の積み**: ヘックスにある選択可能な対象を、次の順序の配列として得る純関数を`src/ui/`に置く（名称は実装担当が決める。例`resolveTileTargets(state, position)`）。順序は`同一ヘックスの味方ユニット（現行の並び順）→ 施設 → 検問所 → 可視ゾンビ → 空き道路／空きヘックス`。可視ゾンビは現行の`getPlayerVisibleTileKeys`の範囲だけを含め、視界外の敵を含めない（フェアプレイ境界）。破壊済みユニットと搭乗中ユニット（`transportedByUnitId`）は含めない。

**S-2 初回タップ**: 選択が別ヘックスにある、または未選択のとき、積みの先頭を選択する。現行の地図モードの優先順位（味方ユニット→施設→検問所→可視ゾンビ→ヘックス）と同じにする。

**S-3 再タップで順送り**: すでに選択しているヘックスを再タップし、積みの**主要対象（味方ユニット・施設・検問所）が2個以上**あるとき、次の主要対象へ進む。最後の次は最初へ戻る。空きヘックス／道路は順送りに含めず、Stack Picker（S-5）から選ぶ。主要対象が1個だけのとき、再タップは現行仕様5.3どおり未選択へ1段戻す（ユニット選択中の同Unit再タップ、`cancelUnitInteractionLevel`）。移動・攻撃モード中、確認待ち中、建設・検問所の配置モード中のタップは現行動作を変えない。

**S-4 モード切替の廃止**: `NavigationMode`による選択優先の分岐を廃止する。次の機能はモードに関係なく利用できるようにする。

- ユニット選択時の盤面上メニュー（現行は`navMode !== 'map'`で出ない、[controller.ts:4298](../../src/ui/controller.ts#L4298)付近）
- 空きヘックス選択時の局所建設ボタン、障壁（有刺鉄線）建設（現行は内政モードのみ、[controller.ts:5756](../../src/ui/controller.ts#L5756)、[controller.ts:5767](../../src/ui/controller.ts#L5767)付近）
- 空き幹線道路の選択と、検問所の局所建設

**S-5 Stack Picker**: 積みの主要対象が2個以上のとき、選択中ヘックスの近くに`◀ n/N ▶`と現在の対象名を持つコンパクトなUIを盤面上に表示する。44px以上、画面端では盤面内へ収め、パン・ズーム・リサイズへ追随する（既存の`placeBoardContextUi`の配置規則を再利用してよい）。ユニットメニューが上に出るときは下、下に出るときは上に置き、重ならない。空きヘックス／道路もこのUIから選べる。現行のシート内の同一ヘックスタブは、シートの固定ヘッダー側へ移し、スクロールで消えないようにする。

**S-6 下部ナビ**: `作戦図`・`内政`・`ターン終了`の3つにする。`ターン終了`は主ボタンとして広く、手動保存は`⋯`メニューへ移す（U-5）。`作戦図`と`内政`は「画面」の切替であり、選択優先の指定ではない。

**S-7 内政ビュー**: `内政`を選ぶと、シートを展開し、未選択時の概況（危機、人口の所在地、支線、重要イベント、次ターンのペナルティ予測、建設）を表示する。内容と開閉規則は現行仕様5.2の概況アコーディオンと同じ（初期はCriticalのある危機だけ展開、Eventは最新10件ずつ増やす）。内政ビューで盤面を選択したら、対象を選んで作戦図へ戻り、シートは標準にする。`作戦図`を選ぶと選択を維持して標準へ戻る。地図タブの未選択時は概況を出さない（S-9）。

**S-8 ナビ切替時の整理**: 切替時に、現行どおり移動・攻撃・確認待ち・配置モードの途中状態を解除する。

**S-9 未選択時の作戦図シート**: 折りたたみ（約44〜64px）を既定とし、1行のヒント（`ユニットか施設を選択`）だけを出す。概況の人口要約は出さない。

**S-10 テストの置換**: `resolveTileSelection(state, position, mode)`とその単体テスト（[controller.test.ts](../../src/ui/controller.test.ts)の256〜289、512〜513行付近）は、S-1〜S-3に置き換える。「地図モードは味方ユニット優先」「内政モードは施設・検問所だけ」という期待値は、本書（確定後）の根拠で新仕様へ更新する。

### 5.3 ボトムシート（B）

**B-1 3段階の中身**: シートは`collapsed / standard / expanded`の3状態を維持し、**状態ごとに表示内容を変える**（`renderSheetBody`が状態を参照する）。内容は対象種別ごとのビューモデル（§5.4）から作り、HTMLの組み立てと分離する。

| 状態 | 内容 | 高さ（現行値を基準。実装担当が調整可） |
| --- | --- | --- |
| collapsed | 対象名（日本語）、状態チップ、要点2個まで。本文なし | 約64px |
| standard | 対象名、要点（最大5個）、例外行（最大2行）、主要操作、`詳細 ▾` | 現行の`clamp(158px, 25dvh, 224px)` |
| expanded | standardに加え、詳細セクションをすべて開く。内部スクロール | 現行の最大54dvh |

**B-2 standardはスクロールなしで読める**: 390×844で、既定の標準内容（ユニット、ゾンビ、各施設種別、検問所、空きヘックス）が縦スクロールなしで収まる。例外行が3行以上になる場合だけ、主要操作を固定したまま例外を内部スクロールにしてよい。

**B-3 主要操作は固定領域**: 対象名・主要状態・合法な主要操作は固定領域に置き、内部スクロールに依存させない（現行仕様5.2）。詳細Formは対象内で**同時に1つだけ展開**する。

**B-4 既定の状態**: ユニット・施設・検問所・ゾンビ・ヘックスの選択時は`standard`。未選択の作戦図は`collapsed`、内政ビューは`expanded`。選択を解除したときは`collapsed`へ戻す。ユーザーが手動で切り替えた状態は、同じ選択の間だけ保持してよい。

**B-5 状態ラベルの廃止**: 「標準」「展開」「折りたたみ」の文字ラベルを表示しない（ハンドルの`aria-label`には残す）。ハンドルのドラッグ・タップで切り替える動作、Safe Area、44px以上のタッチ対象は維持する。

### 5.4 対象別パネル（P）

共通: IDは見せない。名前は日本語で、同種が複数あるときだけ`機動隊 1`のようにIDの末尾番号を付ける（番号が無ければ付けない）。完全なIDは詳細に出す。例外優先（P2）に従い、正常な項目は行を出さない。

| 対象 | 折りたたみ | 標準の要点（最大5） | 標準の例外行 | 標準の主要操作 | 詳細（展開） |
| --- | --- | --- | --- | --- | --- |
| 味方ユニット | 名前・熟練度・HPバー・供給 | HPバー+数値、移動力、攻撃回数、燃料、携行軍需品 | 供給外、燃料0（緊急移動）、軍需不足、感染拠点上、昇格待ち | `詳細`（Move/Attack/Waitは盤面メニューが主。Waitはシートにも残してよい） | 熟練度と進捗、燃料予測、携行軍需品、回復予測、射程（基本/実効）、視界、攻撃力、騒音、鎮圧、砲兵・航空の詳細、ID |
| ゾンビ | 名前・HP | HP、攻撃、移動、射程、Wave所属チップ | 追跡ボーナス中 | なし | 攻撃回数など。追跡の説明文はヘルプへ |

| 検問所 | 名前・役割・状態 | 待機/審査/合格/感染の4数、次の到着、供給 | 感染、Final後の到着停止、不合格見込み | 方針セレクト | 維持費、拒否、方針の詳細、再配置、有効化、復旧条件 |

**P-1 衛生・飢餓・感染予測の移動**: 全国の食料/民需不足率・衛生ストレス・蓄積・飢餓死亡は、内政ビューの「予測」セクションへ移す。**全項目が正常（0）のときは`異常なし`の1行**にし、値は詳細へ折りたたむ。小数は2桁まで（`stress`など細かい値は詳細の中だけで3桁可）。施設・検問所のパネルには、**その拠点の感染確率が0より大きい、または感染者がいるときだけ**例外行として出す。

**P-2 原発遠征の要約**: 概況の先頭にある`原発遠征`の`details`は、内政ビューの先頭に1行（状態チップ）として残し、説明文はヘルプへ移す（`RULES_V163`の文はヘルプに既にある）。

**P-3 ルール説明の除去**: パネル内の`tip*`・`muted`の説明段落は、ヘルプの対応節に同じ内容があることを確認して外す。ヘルプに無い説明は、ヘルプへ移してから外す。

**P-4 既存の合法性・拒否理由**: Coreの合法手と拒否理由（無効化したボタンと理由の表示）は現行どおり維持する。標準の例外行に出す理由は、現行と同じ`actionReasonFor`／`localizeActionError`の文言を使い、独自の判定を追加しない。

### 5.5 盤面の表示（M）

**M-1 日本語ラベル**: 盤面の施設ラベル（[board.ts:1688](../../src/ui/board.ts#L1688)付近）は、翻訳キー`t('...')`ではなく、シートが使う施設名の表（`facilityLabel`）を使う。Phase 0で先に直す。**日英どちらのUIでも内部キー・ID・camelCaseが画面に出ない**ことを、盤面ラベル・ユニットのラベル・施設名・検問所名・警告文で確認する。ユニット名のラベル（[board.ts:1801](../../src/ui/board.ts#L1801)付近の`t('police')`など）の翻訳キーも同じ点検を行い、欠けていれば表を使う。

**M-2 文字サイズ**: 盤面の文字は11px以上にし、暗い背景（縁取りまたは半透明の裏地）を付けて、地形の上でも読めるようにする。盤面上のHuman Unitの文字情報は、現行仕様5.5どおり`名前・HP・Attack Charge・補給内外`だけを維持する（項目は増やさない）。

**M-3 Stack Pickerと補給トグル**: §5.1 U-6と§5.2 S-5を満たす。

### 5.6 視覚（V）

**V-1 色の意味**: 通常のUIは濃淡と線だけで構成する。色は`注意（琥珀）`と`危険（赤）`、良好な状態の文字色（緑）だけに使い、青緑・紫など意味のない色の枠を増やさない。色は`:root`のカスタムプロパティ（`--surface-0/1/2`、`--warn`、`--danger`、`--ok`など）にまとめ、触るコンポーネントは16進の直書きを置き換える。CSS全体の一括書き換えはしない。

**V-2 文字**: 読ませる文字は11px（0.6875rem）以上。ラベル専用の`0.58〜0.65rem`は使わない。数値は`font-variant-numeric: tabular-nums`を維持する。

**V-3 重複する`@media`**: HUDの`max-width: 560px`・`359px`の規則が複数箇所に分かれているため、触る範囲で1か所へまとめる。

**V-4 操作域**: ボタン・チップ・タブは44 CSS px以上を維持する。

### 5.7 不具合修正トラック（R）：終了済みSessionのArtifact出力

元資料: [不具合報告](v1.7.0_終了済みセッションのリプレイ出力不具合報告_2026-10-04.md)。事実関係・静的照合・修正候補・回帰テスト案は報告の第2〜8節を正とし、本節は実装担当への要件として要点だけを置く。報告の「未実施」は、本節の作業で実施した検証と区別して記録する。

**R-1 出力の成功**: 勝利・敗北（少なくとも`capitalLost`）で終了した保存済みSessionに対し、公式Session CLIの`artifact`コマンドが、自己完結した公開Artifact ZIPを出力できる。現状は`game_over: The game is over`で失敗する（終了コード1）。現行仕様5.7.4の「AIプレイ終了後に取得でき、既存の途中記録exportも維持する」契約を満たす。

**R-2 進行禁止の維持**: 終了後の`Move`・攻撃・`EndTurn`などのゲーム進行は、従来どおり拒否する。すべての`gameOver`ガードを一括して外さない。内部の保存復元経路を公開Agent／Bridge APIへ無条件に開放しない。

**R-3 参照操作として扱う**: 出力は、元Session、既存の保存、RNG、Revision、公開履歴、拒否記録を変更しない。既存出力への上書き拒否と、途中失敗時の扱いも維持する。

**R-4 整合性保証と公開境界を弱めない**: 版・構造・不変条件の検証、復元後の公開状態の照合を省略しない。Private Stateと非公開情報をZIPに含めない。

**R-5 進め方**:
1. まず再現する。元の保存済み敗北Sessionが無い場合は、終了済み状態の限定fixtureで、`game_over`を理由に失敗するテストを書いて失敗を確認する。元Sessionで再現できなかった場合は、その限界を報告に書く。
2. 修正方針は報告の候補（終了済みsnapshotを読み取り用途で復元する経路を設ける、または公開記録からArtifactを完結させる）から選ぶ。推定原因は、`restorePrivateSessionState`が終了済みsnapshotから作ったEngineに再度`LoadSnapshot`を通し、`step`の先頭の`gameOver`ガードで拒否されること（報告の第5節。`src/agent/game.ts`、`src/session/service.ts`、`src/session/agent-adapter.ts`、`src/core/engine.ts`）。
3. **`src/core/engine.ts`のガードや公開APIの契約に触れる修正は、着手前に根拠と案を親へ返す**。Session・Agent内で完結する修正は、そのまま進めてよい。
4. 報告第8節の回帰テスト案を、受入条件の候補として実施する。実施した範囲と結果を、実施していないものと区別して記録する。

**R-6 検証の区別**: Readerでの読み取り（`SessionService.readArtifact`、`ReplayPackage.open()`）、Coreによる決定列の再実行、ブラウザGUIでの観戦は、それぞれ別の検証として扱い、一方の成功を他方の代用にしない。GUI観戦はUIトラックのブラウザ確認（§8.2）の機会に確認してよいが、未実施なら未実施と書く。

## 8. 試験・検証

### 8.1 自動テスト（仕様に基づく振る舞い）

- **対象の積み**（S-1〜S-3）: ユニット+施設+検問所が重なるヘックスで順序と順送りの循環。主要対象が1個のときの再タップは未選択へ戻る。視界外ゾンビが積みに含まれない。破壊済み・搭乗中ユニットが含まれない。
- **表示規則**: 感染0で感染チップが出ない。警告0で警告チップが出ない。最終襲撃前に勝利進捗が出ない。不足のある資源だけが警告状態になる。`saveStatus === 'failed'`のときだけ保存失敗チップが出る。
- **ビューモデル**: ユニット・施設・検問所の要点が最大5個、例外が条件を満たすときだけ出る。衛生予測がすべて0のときに「異常なし」になる。
- **シート**: 3状態で内容が変わる。標準の既定内容の要素数がB-2の上限以内。
- **日英の表示**: 盤面ラベル・パネルにキー文字列やIDが出ない。
- 既存のUIテスト（[controller.test.ts](../../src/ui/controller.test.ts)、`board.test.ts`、`boardAssets*.test.ts`、`actions.test.ts`ほか）は、新仕様で変わる期待値だけ更新し、他は維持する。
- バグ修正（Phase 0）は、不具合を再現する入力でテストが失敗し、修正後に成功することを確認する。確認できなかった場合はその限界を報告する。

### 8.2 ブラウザでの確認

既存の手段（`.agents/skills/playwright*`、`scripts/browser-*.js`）を使う。次の組み合わせで画面を撮り、**目視と数値の両方**で確認する。

- 画面: 390×844、360×740、1280×720。日本語と英語。
- 状態: ①新規ゲーム直後（未選択） ②ユニット選択（標準・折りたたみ・展開） ③同一ヘックスに部隊と施設がある状態での再タップ ④施設選択（労働者あり・給電あり・停電予測あり） ⑤検問所選択 ⑥空きヘックス（建設可・建設不可） ⑦内政ビュー ⑧警告が出ている状態 ⑨最終襲撃後（勝利進捗の出現）。
- 数値の目標（`#app`の高さに対する`.board-region`の高さ。実装担当が実測して記録する）: **未選択の既定で55%以上、ユニット選択（標準）で45%以上**。盤面より上の帯の合計は140 CSS px以下。横方向のはみ出しなし、ブラウザ警告・エラー0件。
- 現状の基準値（スクリーンショットから）: 盤面約30%、盤面より上の帯約300 CSS px。
- 目標を満たせない場合は、値を黙って下げず、実測値と理由を親へ返す。

### 8.3 回帰の範囲

- 必須: `npm run typecheck`、`npm run build`、`src/ui/`の全テスト、上記のブラウザ確認。
- `src/core/`・共有型・保存形式に触れた場合は、親へ報告したうえで`npm test`の全体を実行する。UI限定の変更では、成功済みの全体テストを根拠なく反復しない。

- 長時間のシミュレーション（`test:balanced`など）は対象外。
