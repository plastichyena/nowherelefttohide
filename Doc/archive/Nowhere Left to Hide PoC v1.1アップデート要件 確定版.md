# 1. 目的

v1.1では、民間人口を所在地のない抽象プールとして退避できる問題を解消し、都市を居住地・人口供給元・避難先として機能させる。同時に、人口集中へ過密コストを課し、初期ゾンビ接触とモバイル上の人口操作を調整する。

中心となる体験は次のとおり。

> 施設から人を逃がすことはできるが、人を盤面から消すことはできない。人口を集中させれば過密になり、分散させれば守る範囲が広がる。

# 2. 用語と人口モデル

## 2.1 人口分類

民間人口は常に次のいずれかへ所属する。

- 州都住民
- 地方都市住民
- 生産施設労働者
- 検問所の避難民（審査待ち）
- 検問所の審査中避難民
- 検問所の配置待ち合格者
- 施設または検問所の感染者

警察・州兵の人口は民間人口から転換済みのユニット人口として別に追跡する。

## 2.2 未配置人口の廃止

- `unassignedPopulation`、旧`unemployed`に相当する所在地のない人口を正データとして持たない。
- 人口移動は1つのGameAction内で移出と移入を完了させる。
- 保存状態、Action間、ターン終了時のいずれにも未配置人口を残さない。
- 未配置人口を理由とするEndTurn禁止は設けず、人口保存則によって不正状態を防ぐ。
- UIの主要人口表示は所在地別とし、「就業者 / 無職者」を主概念にしない。

## 2.3 人口保存則

人口を変化させる各GameActionおよび自動処理の前後で、次の収支が説明可能でなければならない。

```text
都市住民
+ 生産施設労働者
+ ユニット人口
+ 検問所の3健常者プール
+ 感染者
+ 累積死亡者
```

移住・配置・撤収・編成だけでは総人口を増減させない。難民受入、感染変換、死亡、ユニット損失等の理由付き変化はEvent Logへ記録する。

# 3. ターン開始時の都市スナップショット

## 3.1 作成条件

各プレイヤーターン開始時に、その時点でプレイヤー所有かつ陥落していない州都・地方都市を順位表へ記録する。各都市には、人口操作へ利用できるかを示す資格も同時に固定する。資格には次のすべてを必要とする。

- 感染者が0
- 前ターン以前に確保または復旧済み

感染中の都市も順位と資源不足時の人口損失順には含めるが、供給・受入・移住・編成には使用しない。ターン途中に新規確保または感染から復旧した都市は順位表や利用候補へ追加せず、次のプレイヤーターンから利用可能にする。

## 3.2 供給順位

ターン開始時人口の多い順とする。同数時は固定マップの`facilityId`昇順とし、州都を特別優先しない。

用途:

- 生産施設への労働者供給
- 警察・州兵編成時の人口消費
- 資源不足時の都市人口損失順

## 3.3 受入順位

ターン開始時人口の少ない順とする。同数時は`facilityId`昇順とする。

用途:

- 生産施設から撤収した労働者の帰還
- 審査済み避難民の自動配置
- その他、自動処理で都市へ戻る民間人口

## 3.4 凍結と利用不能化

- ターン途中の人口変動では順位を再計算しない。
- ターン開始時に感染中だった都市は利用資格なしで固定し、そのターン中に回復しても候補にしない。
- スナップショット後に感染・陥落した都市は利用不能とし、順位を詰め直さずスキップする。
- 次のターン開始時に全条件と順位を再計算する。

# 4. 人口移動

## 4.1 生産施設への配置

- 対象は所有中、非感染、陥落していない生産施設とする。
- 新規確保・復旧した施設は次のプレイヤーターンから操作可能とする。
- 追加人数は供給順位の都市から順に差し引く。
- 1都市で不足する場合は次順位の都市から続けて差し引く。
- 生産施設のハード上限25人を超えない。
- 安全な供給候補だけで必要人数を賄えなければAction全体を拒否し、状態を変更しない。

## 4.2 生産施設からの撤収

- 減らした労働者は同じAction内で都市へ帰還させる。
- 受入順位の各都市をソフトキャップまで順に満たす。
- 全候補都市がソフトキャップへ達した後の残人数は、固定した受入順位で1人ずつ巡回配置する。
- 安全な受入候補がない場合、撤収Actionを拒否する。

## 4.3 都市間移住

`TransferPopulation`相当の原子的GameActionを追加する。

- 移動元・移動先はターン開始時スナップショットに含まれる安全な所有都市とする。
- 距離を問わず、移動元人口を上限として任意人数を即時移動できる。
- 移動先はソフトキャップを超過できる。
- 感染中、陥落済み、新規確保直後、復旧直後の都市は移出・移入に使用できない。
- 不正Actionは人口を一切変更しない。

## 4.4 UI

- 生産施設の労働者指定にはスライダーと数値入力欄を併用する。
- 双方を即時同期する。
- 数値入力は整数へ正規化し、範囲外をクランプする。
- 最小値は0、最大値は施設上限と現在の供給可能人口から算出する。
- `inputmode="numeric"`を設定する。
- タッチ対象は原則44 CSS px以上とする。
- `-1` / `+1`ボタンはv1.1必須範囲に含めない。
- 新規確保・復旧した施設が次ターンから操作可能になることを、無効理由、ヘルプまたはTipsに明記する。

# 5. 都市人口と過密

## 5.1 ソフトキャップ

- 州都: 100人
- 地方都市: 50人

Configで変更可能とする。都市人口はソフトキャップを超過できる。

## 5.2 都市の民需品生産

```text
都市民需品生産 = min(都市人口, SoftCap)
```

ソフトキャップ超過人口は追加の民需品を生産しない。都市は人口が1人以上であれば従来の電力要件に従う。

## 5.3 過密率

都市ごとに次を計算する。

```text
都市過密率 = max(0, 都市人口 - SoftCap) / SoftCap
州全体過密率 = Σ 都市過密率
```

州全体過密率に上限を設けない。計算は整数比を用い、浮動小数点誤差で切り上げ結果が変化しないようにする。

## 5.4 追加消費

EndTurn実行時点の人口を使用し、その直後の経済処理へ適用する。

```text
追加食料消費 = ceil(通常食料消費 × 州全体過密率)
追加民需品消費 = ceil(通常民需品消費 × 州全体過密率)
```

- 過密都市が1つ以上あり、通常消費が0より大きい資源の追加消費は最低1とする。
- 最終消費は通常消費と追加消費の合計とする。
- 軍需品、燃料、電力には適用しない。
- EndTurn予測はターン中の人口移動に応じて即時更新する。
- 経済処理後に加入した避難民は次のEndTurnから過密計算へ含める。

# 6. ユニット編成

## 6.1 編成拠点

- 警察: 州都・地方都市
- 州兵: 州都のみ
- 生産施設ではどちらも編成不可
- 新規確保・復旧した都市は次のプレイヤーターンから編成可能

## 6.2 人口消費

- 必要人口は供給順位の都市から順に直接徴用する。
- 1都市で不足する場合は次順位から差し引く。
- 感染・陥落等で利用不能になった候補はスキップする。
- 民間人口以外のコストと予約完成タイミングはv1.0を維持する。
- 編成後に州全体の健全民間人口が0になるActionは不正として拒否する。

# 7. 敗北・人口損失・陥落

## 7.1 敗北条件

次のいずれかが成立した瞬間に敗北する。

1. 州都が陥落する。
2. 所有中の州都・地方都市・生産施設にいる健全民間人口の合計が0になる。

ユニット人口、検問所の3プール、感染者は2の敗北回避に数えない。州都は住民0でも所有を維持し、感染等で陥落しない限り1の敗北にはならない。

## 7.2 人口0施設

- 手動移住・配置・撤収・資源不足で人口0になった施設は所有を維持する。
- 無人・停止状態となるが、陥落、ゾンビ生成は発生しない。
- 感染処理によって健常人口0になった施設は陥落する。

## 7.3 食料・民需品不足の損失順

1. ターン開始時の供給順位で都市住民を減らす。
2. 都市住民で不足する場合、確保順が新しい生産施設から労働者を減らす。
3. 生産施設の確保順も同じ場合は`facilityId`昇順とする。
4. 食料不足を先に処理し、その結果へ民需品不足を続けて処理する。

資源不足で個別施設が0人になっても陥落させず、州全体の健全民間人口が0になった時点で敗北させる。

# 8. 検問所と避難民

## 8.1 3つの健常者プール

検問所ごとに次を保持する。

- `waiting`: 避難民（審査待ち）
- `screening`: 審査中
- `approved`: 配置待ち合格者

配置待ち合格者は所在地を検問所に持つため未配置人口ではない。配置待ち中は食料・民需品を消費しない。

## 8.2 合格者の配置

- 審査完了後、安全な受入候補都市があれば受入順位で自動配置する。
- 各都市をソフトキャップまで順に満たし、全都市到達後は順位順に1人ずつ巡回する。
- 安全な都市がなければ`approved`へ加える。
- 安全な候補が生じた次のプレイヤーターン開始時に自動配置する。

## 8.3 ゾンビ襲撃による感染

ゾンビが検問所タイル上でゾンビターンを終了した場合、感染人数を次の順で健常者から感染者へ変換する。

```text
waiting → screening → approved
```

## 8.4 内部感染

ゾンビが去った後の毎ターンの内部感染も次の順とする。

```text
waiting → screening → approved
```

## 8.5 配置待ち合格者の潜伏感染

- 審査完了時に従来どおり方針別の感染発生判定を行う。
- 安全な都市へ配置できる場合は、配置後に健常人口のいる所有施設からSeed付き乱数で発生先を選ぶ。
- 配置先がなく`approved`へ留まる場合は、潜伏感染を検問所内で即時発生させる。
- この即時変換だけは次の順を使用する。

```text
approved → screening → waiting
```

- 通常は感染予定人数が当該バッチの合格者数以下であるため、`approved`だけで完結する。後続2プールはConfig変更等に備えた決定的フォールバックである。
- 以降の内部感染拡大は8.4の通常順へ戻す。

## 8.6 検問所陥落

`waiting + screening + approved = 0`かつ感染者が1人以上になった時点で検問所を陥落させる。配置待ち合格者の潜伏感染による全滅も即時判定する。荒廃化とゾンビ生成はv1.0を維持する。

# 10. GameState・Action・保存

## 10.1 GameState

最低限、次を明示的に保存する。

- 都市別住民数
- 生産施設別労働者数
- ターン開始時の供給順位・受入順位と利用資格
- 検問所の`waiting`、`screening`、`approved`、`infected`
- 人口移動と損失を検証できる統計・イベント

導出値は単一の正データから再計算し、相互に不一致な人口合計を保存しない。

## 10.2 GameAction

- 既存`AssignWorkers`は都市供給・都市帰還を含む原子的Actionへ変更する。
- 都市間移住Actionを追加する。
- すべてValidatorとGameEngineを経由する。
- UI、Headless、Random Test Agentは同じActionと合法条件を使う。
- 人口保存則に反するActionは状態を変更せず理由付きで拒否する。

## 10.3 セーブ互換性

- Game Versionをv1.1へ更新する。
- v1.0以前の自動保存、セーブコード、JSONとの互換性を持たせない。
- 旧形式を検出した場合は状態へ適用せず、旧バージョンのため読み込めない旨を表示する。
- ブラウザ保存領域に旧データが残っている場合も同じ案内を表示し、「最初から」を選ぶよう促す。
- 旧データを自動変換、自動削除、自動上書きしない。

# 11. ヘルプ・表示要件

最低限、次を日本語・英語のヘルプまたはTipsへ追加する。

- 民間人口は都市・施設・検問所のいずれかに存在し、未配置プールへ逃がせない。
- 施設撤収時は人口が都市へ自動帰還する。
- 都市はソフトキャップを超過できるが、民需品生産上限と追加消費が発生する。
- 新規確保・感染から復旧した施設は、次のプレイヤーターンから人口操作・編成に使用できる。
- 警察は都市、州兵は州都でのみ編成できる。
- 旧バージョンのセーブデータは読み込めない。

Actionが無効な場合は、単にボタンを無効化するだけでなく、該当する理由を確認できる表示を行う。

# 12. 必須テスト

## 12.1 人口保存

- 配置、撤収、都市間移住、編成で人口が意図せず増減しない。
- Action失敗時に部分的な人口移動が残らない。
- 所在地のない民間人口が存在しない。

## 12.2 順位と利用資格

- 供給・受入順位が人口と`facilityId`で決定される。
- ターン途中の人口変動で順位が変わらない。
- 感染・陥落した候補をスキップする。
- 新規確保・復旧した施設は次ターンまで利用できない。

## 12.3 受入分配

- 順位順にソフトキャップまで配置する。
- 全都市がソフトキャップ到達後、順位順に巡回配置する。
- 安全な都市がない場合、合格者が検問所に残る。

## 12.4 編成と敗北

- 警察・州兵の編成拠点制限が機能する。
- 人口を供給順位どおり徴用する。
- 最後の健全民間人口を使う編成を拒否する。
- 健全民間人口0と州都陥落を正しく判定する。

## 12.5 過密

- ソフトキャップを超過できる。
- 都市民需品生産がソフトキャップで止まる。
- 複数都市の過密率を加算する。
- 食料・民需品の追加消費を正しく切り上げる。
- EndTurn予測と実消費が一致する。

## 12.6 検問所

- 3プールの集計と保存・復元が一致する。
- 襲撃と内部感染が`waiting → screening → approved`で変換する。
- 配置待ち合格者の潜伏感染だけが`approved → screening → waiting`で変換する。
- 全健常者0で即時陥落する。

## 12.7 UI・保存・初期状態

- スライダーと数値入力が同期し、不正値をクランプする。
- ヘルプ・Tipsと無効理由が表示される。
- v1.0の自動保存、コード、JSONを理由付きで拒否する。
- 初期人口配置と初期ゾンビ4座標が仕様どおりである。
- Turn 1のゾンビ行動で初期所有施設へ到達できない。

## 12.8 回帰

- 既存Coreテストをv1.1仕様へ更新して通す。
- Random Test Agentが未配置人口なしでEndTurn可能な合法手を選べる。
- 複数Seed試験で人口保存則、非負、不正状態、無限ループ違反がない。
