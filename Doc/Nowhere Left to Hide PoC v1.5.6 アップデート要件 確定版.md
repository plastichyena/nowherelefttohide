## 1. 目的・範囲

- AIが公開済みの情報を見落としにくくし、施設停止・人口操作不能の理由と対処を判断対象の近くに示す。
- 復旧案内と実処理を一致させ、感染者0の荒廃した恒久施設を駐留で再確保できるようにする。
- 有刺鉄線を、索敵能力を持たない、破壊可能な防衛障害物として追加する。横に防衛線を形成できる一方、州都へ向かう多重配置とその場での反復再建による過剰な遅延を抑える。
- 道路生成、道路のMP1、固定地形、施設配置、人口維持費、Wave編成、既存Unitの能力値は変更しない。
- 壁追加と情報修正以外のBalanced Agentの全面的な戦略改修、勝率保証、ランダムマップは含めない。
- Game CoreをPhaser/UIから分離し、状態変更はGameAction → GameEngine経由とする。UI・AI・Forecastは共通Core Queryを使う。

## 2. AI向け情報開示と復旧修正

### 2.1 調査結果の扱い

- v1.5.5のCompactには、既に`maintenancePopulation`、`maintenanceBreakdown`と施設の`status`、`owner`、健常人口、感染人口がある。これらを新設項目として重複追加しない。
- Claudeの表示スクリプトで省略されていた項目と、API自体の不足を分ける。推奨CLI利用例を改善する。
- run2のT15の労働者配置不能は、州都・city-1の感染と配置可能都市人口0によって説明できる。都市人口総数と利用可能人口を区別する。
- 都市間移送の`ineligible_city`を、都市間移送機能そのものの禁止として説明しない。
- Gas攻撃プレビューは既存実装を維持・検証する。今回の自己申告だけで計算バグと断定しない。
- 同一Seedの2戦の勝敗・累積人数だけで道路の過剰な効果や壁の必要性能を断定しない。

### 2.2 Compactと推奨表示

- 既存の維持人口、Food/Civilian Goodsの基本・過密・住宅停電追加・合計維持費、資源終値予測、施設状態を保持する。
- 推奨表示例は上記に加え、利用可能都市人口、全4支線の管理状態、重要施設の変化、停止理由と停止の影響、未実行Actionを毎回確認できるようにする。
- `PLAY_WITH_AI.md`、機械可読API、Windows/Linuxの推奨利用経路を一致させる。利用例が必要フィールドを省略して情報欠落を再発させないようにする。
- 重い詳細配列をCompactへ無制限に追加しない。少数の重要項目と件数、同じRevisionの詳細Queryへの導線を返す。要約で省略したことを明示する。

### 2.3 支線と人口流入

- Compactは検問所オブジェクトの有無と無関係に、north/east/south/westの4支線を常に返す。
- 支線ID、管理中/未管理、Active Checkpoint IDまたはnull、現在方針、次回到着Turnまたはnull、到着終了を含める。
- 直近の公開流入結果を支線別に示す。未管理素通り、検問所経由の受入、Queueの変化を区別する。累積値・当該処理の変化・次回予告を混同しない。
- normal/strict/passThroughとwaitingのみを対象とするTurn Awayの違いを表示する。strictやQueue滞留を「流入ゼロ」「維持費ゼロ」と説明しない。
- Hiddenな拒絶Counter、将来Wave Bonus内訳、将来乱数・未公開の到着人数を開示しない。

### 2.4 施設変化・停止原因・危機

- Action/EndTurn応答は、公開施設の所有変更、陥落、復旧開始・完了、人口変化、稼働停止・再開の重要な差分をIDと理由付きで示す。
- 差分は直前の確定Revisionとの比較とし、同一Revisionの再取得で新規変化を捏造しない。比較元がないstatus/newでは現在状態を示し、変化として扱わない。
- 発電施設喪失、Fuel制約、給電割当不足、感染、復旧待ち、人口不足を区別する。公開Eventで確認できる原因と、公開状態からの推定を区別する。
- Compactの給電予測に、停止する重要なPlayer施設のIDと理由を残す。件数のみの`unpoweredFacilities`を、未所有施設を含む件数だけで危機と解釈させない。
- 電源喪失→生産停止→予測収支悪化を、共通の経済Queryから示す。建設/人口移送後の確定状態の予測で、住宅への給電により止まる生産施設を識別できるようにする。
- 現在の赤字、当Turnの不足、条件付きの継続赤字リスク、確定敗北を区別する。未計算の複数ターン先の枯渇や「回避不能」を保証しない。
- 大きな生産停止・電源喪失を危機として明示する。既存の公開情報境界とplay-turnの停止契約を維持し、細かなadvisoryを全てcriticalへ昇格させない。

### 2.5 人口操作不能の理由

- TransferPopulation候補は移送元・移送先それぞれの不適格理由を返す。感染、未所有、荒廃、新規確保/復旧による次Turn待ち、Turn開始Snapshotの資格、Action予算、供給可能人口不足を区別する。
- AssignWorkersは対象施設の不適格理由と、人口供給元の不足を分ける。都市総人口、健常住民数、今回利用可能な人口を混同しない。
- 合法手の列挙にないことを理由説明の代用にしない。対象別Queryから禁止理由を取得できるようにする。
- 任意整数の合法人口移送、Turn開始Snapshot、既存の人口供給/受入順序を維持する。理由表示のために途中のSnapshot資格を再計算しない。

### 2.6 恒久施設の復旧

- 感染者0・ruinedの再確保対象となる恒久施設は、同Hexに生存Human Unitが駐留し、Enemy Unitが同Hexにいなければ再確保できるようにする。
- 進入完了時に判定する。既に駐留している場合も、自動鎮圧の処理時点に同条件を再評価し、出入りのやり直しを要求しない。自動判定のために新しい任意のState変更入口を追加しない。
- 感染者0の再確保には鎮圧用Charge・軍需品を消費しない。感染者が残る施設は既存鎮圧を必要とする。
- 復旧後はPlayer所有・人口0とし、人口操作/編成は次のPlayer Turnから可能にする。生産再開には人口、電力等の既存条件が必要であり、復旧と生産再開を同一視しない。
- 建設施設の破壊時消滅/復旧不能、Army Baseの予約・報酬・専用軍需、Windの既存停止復旧規則は維持する。終局した州都の再確保でゲームを復活させない。
- `recovery`は実処理と同じ条件判定から生成する。満たした駐留条件をmissingと返さず、未定日時nullと復旧不能を分ける。
- 普通の鎮圧で感染者が0になった場合、Enemy排除後、既に感染者0で駐留した場合を同じ復旧契約へ収束させる。

### 2.7 攻撃プレビュー

- 既存のGas撃破プレビューへの取得導線を推奨操作例へ含め、味方の被害・死亡見込みを省略しない。
- 有刺鉄線上のHumanへの通常戦闘予測は、攻撃値、壁へのDamage、残壁HP、Humanへの貫通Damageと残HPを返す。
- 直接攻撃の確定結果と、敵フェーズの移動・反撃・迎撃・Gas連鎖など条件付きの結果を分離する。
- Hidden Enemyの存在や内部Targetをプレビューの有無・フラグから漏らさない。

## 3. 有刺鉄線（Barbed Wire）

### 3.1 基本性能

| 項目 | 確定仕様 |
| --- | --- |
| 日本語/英語表示 | 有刺鉄線 / Barbed Wire |
| 最大HP | 10 |
| 建設費 | Civilian Goods 5 + Military Goods 5 |
| 個数上限 | 固定上限なし。配置資格と通常Action予算は適用 |
| 修理・自然回復 | なし |
| 視界・補給・人口・生産・電力 | 提供せず、需要・維持費も持たない |
| Human | 通過・停止可能。進入先の実効移動コスト5 |
| Zombie | HPが残る間は進入・通過・停止不可。隣接から攻撃可能 |
| HP0 | 直ちに消滅。元の基礎地形・道路を維持 |

- 施設/Unitではなく、HPを持つ独立した障害物として扱う。既存の施設上限、Urban判定、施設Vision、Zombie人口Target、供給Sourceへ暗黙に混入させない。
- 地形防御、LOS遮蔽を追加・除去しない。元のForest等のLOSは残る。
- Humanの進入MP5は道路MP1・地形コストより優先し、追加5ではなく合計5。水域・Spawn Reserve等の通行禁止は解除しない。
- 移動力不足やEmergency Movementでも同じMP5を要求し、足りなければ入れない。Fuelは既存の実移動Hex数による式を維持し、MP5を5Hex分のFuelと扱わない。
- Humanが壁上から退出する際は、進入先Hexのコストを払う。退出時の追加壁コストはない。
- 任意撤去・売却・返金・アップグレードは追加しない。

### 3.2 建設

- BuildBarbedWire相当のGameActionを追加し、1回に1Hex、内政Action枠1を消費して即時完成する。建設Unitや労働者は要求しない。
- 現在視認中、補給内、通行可能、Spawn Reserve外の空きHexだけを許可する。
- 既存施設・建設中施設・荒廃施設・Checkpointとその残存跡、既存壁、Human/Zombie UnitのあるHexには建設不可。
- 幹線/接続道路上も建設可能。Checkpoint用の幹線資格や既存施設用の幹線建設禁止を有刺鉄線へ流用しない。
- Enemy隣接地には建設不可。Hidden Enemyの存在を候補の合法性から漏らさないよう、隣接6Hexも現在視認できることを建設資格とし、その全HexがEnemy不在であることを確認する。盤外Hexは視認確認対象から除外する。
- 3.3で新設壁と不適格な前後関係になる可能性がある距離1/2のHexも、現在視認できることを要求する。そこでの既存壁の有無を公開情報だけで判定し、視界外の壁破壊を建設候補の変化から漏らさない。視認不足は敵/壁の実在にかかわらず同じ理由で拒否する。
- 補給喪失や視界喪失で既存壁を消滅させない。
- 壁のあるHexへの後続の施設/Checkpoint建設・移設を禁止する。建設順で施設共存禁止を回避できないようにする。
- 資源不足、不適格、古いRevisionの拒否は資源・Action枠・State・RNGを変更しない。

### 3.3 放射方向の間隔制限

- 目的は横につながる防衛線を許し、州都へ向かって短い間隔で壁を重ねる配置を禁止すること。
- 以下を確定規則とする。州都C、異なる2壁A/Bについて、地形・道路・障害物を含めない最短Hex Distanceをdとする。
- Aが内側になるようd(C,A) <= d(C,B)と並べる。`d(C,B) = d(C,A) + d(A,B)`なら、州都への最短経路上で前後に並ぶ組とする。
- この組は`d(A,B) >= 3`を必須とする。すなわち間に少なくとも2Hexを置く。1または2なら建設不可。
- 州都から等距離の別Hex同士は横方向の配置として許可する。単なる「全壁同士の距離3以上」にはしない。
- 生存する全壁の組へ適用し、建設順や連結成分ごとの判定で回避させない。HP0で消滅した壁は制限対象から除く。
- 任意の敵の現在Target・Hidden経路には依存しない。州都を中心とする固定ルールとし、UI/AIで理由を再現できるようにする。
- 直線・斜め・折れた最短経路、同半径の連結、2Hex間隔、建設順逆転の図とfixtureを実装時に用意する。

### 3.4 壁への攻撃

- 全Zombie種は隣接Hex Distance1から攻撃できる。壁単独への攻撃もAttack Chargeを1消費し、DamageはそのZombieの実効攻撃力とする。
- 壁に地形防御・回避・反撃・感染・Reanimation・熟練度を付与しない。壁破壊をUnit KillやVeteran進捗へ加算しない。
- Humanから壁だけへの攻撃Actionは追加しない。壁はZombieのUnit占有制約を解除せず、他のZombieが隣接攻撃位置を占有している場合に同じ位置へ重ならない。
- 空き壁への攻撃はHuman Combat Noiseを発生させない。壁上Humanとの戦闘では通常のHuman Combat Noiseを維持する。
- HP0にした時点で壁を除去し、過剰Damageを周囲や後続Hexへ波及させない。壁上Humanへの攻撃の場合だけ3.5の貫通を適用する。
- 壁が残り、攻撃Chargeも残る場合は、同一敵フェーズに再攻撃できる。Hordeの2 Chargeは2回分として働く。

### 3.5 Humanへの肩代わり

- Humanが有刺鉄線のあるHex上で通常攻撃・反撃・迎撃のDamageを受ける場合、同Hexの壁が先に肩代わりする。壁がない/HP0なら通常処理とする。
- 攻撃側の既存の軍需不足補正等を適用した実効攻撃DamageをD、壁HPをHとする。壁Damageは`min(D,H)`、貫通分は`max(0,D-H)`とする。
- 壁自体への地形軽減は行わない。貫通分だけにHuman側の既存地形防御・端数処理を1回適用する。貫通分0ならHuman Damageは0で、最低1Damage規則を適用しない。
- 例: 壁HP10、Damage15、Humanに地形防御なしなら壁が消滅しHuman Damage5。壁HP10、Damage5なら壁HP5、Human Damage0。
- Humanを対象にした攻撃は、壁が全量肩代わりしても1回の通常戦闘である。生存Humanは既存の射程・Charge・軍需条件で反撃可能。壁Damageを理由に追加反撃や追加Charge消費を発生させない。
- 壁上Humanへ隣接したZombieは既存のHuman隣接停止を受ける。Humanへの攻撃で壁を壊しても、Human攻撃後の再移動禁止を維持する。
- Gas死亡爆発は肩代わり対象外とし、既存どおりHumanへ直接作用する。Gas爆発で壁HPは減少しない。感染・資源不足・その他の非戦闘損失も壁で防がない。
- Humanが同Hexにいる場合に、空の壁への攻撃として扱ってHumanへの貫通・反撃を回避する処理はしない。

### 3.6 Zombie移動・経路更新

- 既存Target優先順位を維持し、壁そのものに人口誘引を付けない。目的地への経路を塞ぐ壁を突破対象として扱う。
- 壁を単に永久通行不可として最短経路から除外し、完全な防衛線を前にZombieが無期限にidleになる実装は禁止する。迂回と突破の両方を探索対象にする。
- 経路評価は壁HP・攻撃力・残Chargeと通常移動コストを用いた決定的なルールとし、迂回か突破かの係数・タイブレークは実装時に固定・記録する。追加の乱数消費を必要としない。
- 空き壁だけへの攻撃は、破壊後に残MPで移動を継続できる特例とする。攻撃そのものはMPを消費せず、Chargeだけを消費する。元のTurn移動予算から既に使ったMPを差し引き、移動予算をリセットしない。
- 破壊後Hexへの進入は復元された地形/道路コストを払う。破壊だけで自動進入・ワープさせない。
- 壁破壊直後、同じ敵フェーズ中に通行情報・到達距離・経路cacheを失効させる。破壊した本人と未行動の後続Zombieが新しい盤面を参照する。
- 行動済みZombieへ再行動を与えず、残Charge0のZombieは移動できても追加攻撃できない。既存の移動不能・迎撃停止・Human隣接停止・死亡・終局を解除しない。
- 破壊後に新たなHuman・基地迎撃条件へ入ったら、既存の順序で処理する。壁破壊が移動中の迎撃を免除しない。
- State変更ごとに生存・占有・合法性を再評価し、既に消滅した壁への二重攻撃やHP負値を防ぐ。

## 4. UI・AI・公開範囲

- 日英UI、Help、LegendにHP10、費用、Human MP5、Zombie攻撃、貫通、Gas対象外、修理不可、建設間隔を表示する。タイトルは英語表記を維持する。
- 内政から対象Hexを選び、合法候補と不許可理由を表示する。横方向の合法例と前後の不合法例を示し、内部座標式だけで説明しない。
- 壁と上にいるHumanを同時に識別・選択できるようにし、壁HPとHuman HPを混同しない。既存の施設/Unit選択導線を壊さない。
- 壁はVision Sourceにならない。視界外でのHP変化・破壊・攻撃元を即時通知して索敵手段にしない。
- 公開壁情報は現在可視の壁を正本とする。視界外の建設履歴をUIに残す場合は、最終確認情報と明示して現在存在/HPを保証しない。公開APIにHidden状態の更新を混入させない。
- 攻撃・破壊Event、Metrics、Artifactも同じ公開境界を使い、Hidden Enemy ID・個体数・移動を漏らさない。公開建設数と視認済み破壊数を、内部の実在総数と混同しない。
- AIへ壁の静的規則、現在可視の壁HP、建設候補・理由、Human移動MP/Fuel、肩代わりプレビューを提供する。
- Balancedは壁を含む経路・露出評価と合法Actionを扱えるようにし、同じ不合法配置の反復を避ける。Randomは合法候補から決定的に扱う。独立の壁用AIルールをUI側へ複製しない。

## 5. State・保存・Session・観戦

- 壁ID、位置、現在/最大HP、建設Turnを独立Stateとして保存する。必要な公開最終確認情報がある場合は実状態と分ける。HP0の壁を通行障害として保存しない。
- 壁は動的Stateとし、基礎Map/道路生成器・道路hashを変更しない。同じSeedの初期マップを維持する。
- 建設/被害/破壊はEngine内で原子的に処理し、Query cache・Revision・Replayを整合させる。
- 予定契約番号: App 1.5.6、Rules/State/Config 8.0.0、Save Format15、autosave末尾v15、Agent API/Observation/Bridge 13.0.0、Artifact Schema12.0.0、Session/Checkpoint9.0.0、Balanced8.0.0、Random6.0.0。固定Map IDは`fixed-51x51-v4`を維持する。
- v1.5.5以前のSave/Session/Checkpoint/Artifactは移行・変換せず理由付きで拒否する。旧autosaveを削除・上書きせず、新keyを使う。今回のClaude記録は分析資料とし、新版観戦成功の受入対象にしない。
- Version定数・公開API・配布物を実装時にそろえ、既存のBuild identity・hash・破損検証を省略しない。
