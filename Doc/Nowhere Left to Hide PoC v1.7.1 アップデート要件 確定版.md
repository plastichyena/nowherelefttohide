## 1. 位置付けと範囲

### 1.1 目的

v1.7.1の主目的は、**人間が操作する通常プレイ画面の情報量を減らし、盤面を広く、判断と操作を分かりやすくすること**と、**終了済みSessionから公開Artifactを出力できない不具合の修正**である。ゲームルールやAI向け情報量の刷新は目的に含めない。日本語UIでもタイトルはNowhere Left to Hideとする。

基準画面はスマートフォン縦向き390×844 CSS px。360×740および1280×720でも日英の表示と操作を保証する。盤面比率等の数値合格条件は§8.2に定める。

### 1.3 採用方針

- 同じヘックスの再タップで主要対象を順送りにし、固定ヘッダーの対象切替UIで可視ゾンビや地形にも到達できるようにする。盤面上の別置きStack Pickerは追加しない。
- 「作戦図／内政」は表示する画面の切替とし、対象選択の優先順位を変えない。内政では概況を表示し、作戦図へ戻る際の選択を保持する。
- 正常な説明・状態行を減らす。資源・HP・残行動回数など判断に必要な数値は0でも表示する。値が非公開なら0に置き換えない。
- 5資源アコーディオン、盤面上のユニット操作と確認UI、既存の合法な操作への導線を維持する。
- 標準表示は要点と操作の入口に絞る。シート展開時も詳細を一斉に開かず、必要な項目だけを開く。

## 4. 設計原則

- **P1 常時表示は判断に使う情報だけ**。上部は最大3段。390×844の数値条件は§8.2を必須とする。
- **P2 例外優先**。正常な状態の説明は省略するかチップ1個にする。異常は色と文字・記号の両方で示す。必要な0、Horde進行、選択対象の主要状態は省略対象ではない。
- **P3 重複を減らす**。同じ長文・内訳を同時に常設しない。概要から詳細を開く関係や、人口ボタンと内政から同じ内訳へ到達する導線は許容する。
- **P4 段ごとに内容を変える**。折りたたみは名前と状態、標準は要点と主要操作の入口、展開は必要な詳細を開くための項目一覧とする。
- **P5 説明と判断材料を区別する**。一般的なルール説明はヘルプへ移す。現在の拒否理由、費用、予測被害、操作結果の確認は該当する操作の場所に残す。
- **P6 通常プレイで内部ID・翻訳キーを開示しない**。データ内のIDは保持する。Replay／Liveの公開ユニットID併記はM-4の明示的な例外とする。

## 5. 要件

### 5.1 上部の構成（U）

**U-1 HUD**: 1段に`ターン番号・フェーズ`、`人口 N`、`⋯`メニューを置く。高さ約44 CSS pxを基準とする。ゲーム名はタイトル画面とヘルプに残し、このHUDには出さない。人口は44px以上のボタンとし、タップで市民・労働者・部隊・待機・審査・合格・感染・健常民間人口の内訳を盤面上に重ねて表示する。`populationLocationTotals`等、現行の人口集計を再利用し、感染者などの部分集合を別人口として総人口へ二重加算しない。

**U-2 資源**: 食料・民需・軍需・燃料・電力の5アコーディオンを1段に維持する。4備蓄と電力の需要／供給、展開時の開始量・集約収支・終了見込み・未充足内訳は現行仕様5.1のとおり。Core Forecast上の不足がある資源だけ、ボタン全体の背景と枠を警告色にし、文字`!`を付ける。0の備蓄、電力0/0も必要な値として表示する。

**U-3 状況チップ**: 次の対象を横1行に置く。横スクロールや折返しは使わず、操作域は44 CSS px以上とする。

| 対象 | 出現条件・表示 | タップ先 |
| --- | --- | --- |
| Horde | 常時。`襲撃 T10・あと9`、`襲撃警告 2方向・あと2`、`最終襲撃`等の見出しと進行状態。内容のない「警告 未開始」の別行は出さない | 既存Horde詳細の重ね表示 |
| 感染 | 公開感染者数が1以上のときだけ`感染 N`、赤 | U-1の人口内訳 |
| 警告 | Crisis／戦略警告が1件以上あるとき、最優先の対象名と事象を短い名詞句で表示し、残警告数を付ける。Criticalは赤、Warningは琥珀、Advisoryは青 | 内政ビューを展開し、危機欄を開く |
| 勝利進捗 | `finalHordeStatus !== 'notStarted'`、または最終Waveの待機数／盤面数のどちらかが正のとき。`最終 待機N / 盤面M` | 既存の公開進捗を含むHorde詳細 |
| 保存失敗 | `saveStatus === 'failed'`のときだけ`保存失敗`、赤 | 手動保存画面 |

幅に収まる場合は該当するチップを表示する。収まらない場合は、**Horde＋最優先の異常1件＋「ほかN件」**へまとめる。異常がなければ残項目を「ほかN件」へまとめる。優先はCoreのCritical、保存失敗、感染、Warning、Advisoryの順とし、同種の警告は既存の公開優先順を保つ。勝利進捗は異常として順位付けしない。短縮しても種別・危険度が分かる表示を残す。

「ほかN件」のNは省略したチップの数とし、警告チップ内の残警告数と混同しない。タップで省略項目を重ね表示し、それぞれ元のタップ先へ進める。危機欄ではすべての公開警告を確認できるようにし、Crisisと戦略警告の同じ事象を二重計上しない。表示集約のためにCoreの警告条件・合法性を変えない。

Horde詳細は次Waveの番号、Spawn Turn、残り、方向数、公開済み方向、混成、Wave種別、基礎／確定／出現済み／Pending人数を維持する。「最終襲撃発生ターン」は詳細だけに置く。Warning前の未公開方向や特殊Type抽選結果を追加開示しない。none／periodic／finalの警告状態を維持する。

**U-4 保存状態**: 「保存済み・最終保存ターン」の通常行を廃止し、`saveStatusLabel()`の状態文字列を`⋯`メニュー内へ置く。保存中・未保存の変更はメニューボタンの小さな点とアクセシブルな状態名で示す。

**U-5 メニューと重ね表示**: `⋯`には既存のヘルプ・手動保存・言語切替・保存状態を置く。Board Legendはヘルプ内の入口を維持する。資源、人口、Horde、「ほかN件」、メニューの上部重ね表示は同時に1つとし、初期は閉じる。別の入口のタップ、同じ入口の再タップ、外側タップ、Escape、盤面操作で閉じる。重ね表示で盤面レイアウトの高さを押し縮めない。

**U-6 補給オーバーレイ切替**: 上部HUDから外し、盤面右上に44px以上の意味が分かるトグルを置く。`aria-pressed`と日英のアクセシブル名を持たせ、モード表示・ユニットメニュー・確認UIと重ねない。検問所選択・建設・労働者配置等での自動表示は維持する。

**U-7 未使用コードの整理（任意）**: HTMLに出力されていない`strategic-critical-strip`等は、使用箇所・テストを確認した範囲で整理してよい。新しい警告導線の実装を削除で代用しない。

### 5.2 選択モデル（S）

**S-1 選択候補**: `src/ui/`内の純関数で、同一ヘックスの選択可能対象を次の順で得る。

`味方ユニット（現行の安定した並び順）→ 施設 → 検問所 → 可視ゾンビ → 地形／道路`

破壊済み・搭乗中ユニットは除外する。ゾンビは`getPlayerVisibleTileKeys`相当のプレイヤー視界内にいるものだけを含める。地形は対象があるヘックスにも最後の1候補として必ず用意する。対象のない幹線道路では道路の局所建設情報へ、それ以外では当該ヘックスの地形情報へ到達する。地形と道路を同じ位置の重複候補にしない。情報欄と建設可否は公開情報とCoreの候補に基づく。

**S-2 初回タップ**: 未選択または別ヘックスからのタップはS-1の先頭を選択する。別ヘックスへのタップから移動・攻撃へ暗黙移行しない。

**S-3 同じヘックスの再タップ**: 通常選択中、主要対象（味方ユニット・施設・検問所）が2個以上なら、次の主要対象へ進み、最後から先頭へ循環する。可視ゾンビ・地形／道路はこの循環へ含めずS-5から選ぶ。それらを選択中に再タップした場合は主要対象の先頭へ移る。主要対象が0個または1個なら、再タップで選択を解除する。主要対象1個での解除は既存決定D3を維持する。

移動・攻撃・砲撃・確認待ち・建設・検問所配置・その他の対象指定中は、その操作の既存タップ／キャンセル規則を優先する。対象切替で途中の操作を別対象へ誤適用しない。

**S-4 選択優先のモード依存廃止**: `NavigationMode`による対象優先の分岐を廃止する。作戦図でユニットメニュー、空きヘックスの局所建設、有刺鉄線、空き幹線道路の検問所建設を利用できるようにする。内政から盤面を選んだ場合も、作戦図へ戻ったうえで同じ操作を使える。内政の概況表示中は部隊メニューを表示しない。

**S-5 シート固定ヘッダーの対象切替**: S-1の候補が2個以上なら、シートの固定ヘッダーに対象切替UIを1つ置く。主要対象が1個でも、地形や可視ゾンビが別候補なら入口を表示する。対象名と現在の選択を識別でき、全候補を選べること。表示形式はタブまたはコンパクトな前後切替とし、幅が狭くても一部の候補を選択不能にしない。操作域は44px以上で、シート本文のスクロールで消えず、折りたたみ中も利用できる。

**盤面上の独立したStack Pickerは設けない**。同じ機能を盤面・固定ヘッダー・本文へ重複配置しない。直接の再タップ循環とS-5だけで選択を完結させる。

**S-6 下部ナビ**: `作戦図`・`内政`・`ターン終了`の3つ。ターン終了を広い主ボタンとし、手動保存はU-5へ移す。

**S-7 内政ビューと選択復帰**: 内政へ切り替える際は選択をUI内に記憶し、対象パネルと部隊メニューを隠して概況を展開する。危機、人口の所在地、支線、重要イベント、次ターン予測、建設を現行の概況アコーディオンで表示する。初期はCriticalがある危機欄だけ展開し、重要イベントは最新10件から10件ずつ、現行の上限まで増やす。

作戦図ボタンで戻る場合は、まだ選択可能な以前の対象を復帰して標準表示にする。以前の対象が消滅・搭乗・視界外等で選択不能なら未選択の折りたたみに戻す。内政中に盤面をタップした場合は以前の選択との再タップ判定をせず、S-2でその位置の先頭を選び、作戦図の標準表示へ戻る。危機チップからの内政表示も同じ選択保持規則を使う。

**S-8 途中操作の解除**: ナビ切替時は移動・攻撃・確認待ち・配置・対象指定の途中状態を解除する。記憶した選択を復帰しても途中操作は復帰させない。

**S-9 未選択の作戦図**: 既定は折りたたみ、約44〜64pxに1行の`ユニットか施設を選択`だけを表示する。人口要約や概況を置かない。手動でシートを展開しても概況へ切り替えず、概況は内政から開く。

**S-10 テスト置換**: `resolveTileSelection(state, position, mode)`の旧モード別優先テストはS-1〜S-9の新規則へ置き換える。旧仕様の選択優先に基づく期待値以外は維持する。

### 5.3 ボトムシート（B）

**B-1 状態ごとの内容**: `collapsed / standard / expanded`を維持し、`renderSheetBody`相当が状態に応じて別の内容を表示する。対象別のビューモデルとHTML生成を分離する。

| 状態 | 内容 | 高さの基準 |
| --- | --- | --- |
| collapsed | ローカライズ名、主要状態、要点2個まで。本文なし。必要な対象切替は固定ヘッダーに残す | 約64pxを出発点とし、必要な操作域に応じ調整 |
| standard | 名前、要点最大5個、例外最大2行、主要操作の入口、`詳細 ▾` | 現行`clamp(158px, 25dvh, 224px)`を出発点に調整 |
| expanded | 標準の要約・操作入口と、折りたたまれた詳細項目の見出し。選んだ項目だけ開く | 現行最大54dvhを出発点に調整。本文は内部スクロール |

展開へ切り替えただけで詳細欄をすべて開かない。対象内の詳細セクション／操作Formは同時に1つだけ開く。寸法の基準より§8.2の盤面比率・可読性・操作域を優先し、満たす範囲で調整する。

**B-2 標準の収まり**: 390×844の日英で、ユニット、ゾンビ、各施設、検問所、地形／道路の標準内容が縦スクロールなしで読める。例外が3件以上の場合だけ、最優先2件と残件への入口を残し、残りを開いた際の例外一覧を内部スクロールにしてよい。対象名・主要操作は動かさない。

**B-3 固定領域と操作Form**: 名前、主要状態、対象切替、主要操作への入口は固定領域に置く。標準へ収まらないスライダー・数値入力・編成一覧・移住等は、名前の分かる操作入口を押すとシートを展開し、該当Formだけを開く。必須の既存操作を情報削減のために削除しない。入力・費用・拒否理由・実行結果の確認はそのForm内に揃える。

**B-4 既定状態**: 新しい対象の選択は標準、未選択の作戦図は折りたたみ、内政への切替は展開。手動の高さ・詳細開閉は同じ選択の間だけ保持し、別対象への切替時は初期化する。内政からの復帰はS-7、新規開始・ロードではすべて初期化する。

**B-5 状態名**: 「標準」「展開」「折りたたみ」の文字ラベルは常設しない。ハンドルのアクセシブル名と現在状態は残す。ドラッグ・タップ、Safe Area、44px以上のタッチ対象を維持する。

### 5.4 対象別パネル（P）

共通: 通常プレイでは、詳細・警告・ログ・操作確認・アクセシブル名を含め、生の内部IDや翻訳キーを表示しない。日英の表示名を共通の名前テーブルから得る。同種対象の区別が必要なら`機動隊 1`のような表示用番号と座標を使う。既存ID末尾の番号は表示番号として利用可能だが、内部ID全文を名称にしない。番号がない／重複する場合も座標やUI内の安定した識別名で区別する。表示名のためにデータ内IDを書き換えない。

下表の「要点」は表示グループの上限。検問所の4人口数は1グループと数える。状態と同じ内容を例外行へ重複出力しない。非公開値は現行の「不明」を維持する。

| 対象 | 折りたたみ | 標準の要点（最大5） | 標準の例外 | 主要操作の入口 | 必要時に開く詳細 |
| --- | --- | --- | --- | --- | --- |
| 味方ユニット | 名前・熟練度、HP、供給状態 | HPバー＋数値、移動力、攻撃回数、燃料、携行軍需品 | 供給外、燃料0と緊急移動可否、軍需不足、感染拠点上、昇格待ち | 詳細。移動・攻撃・待機は盤面メニューが主。待機の補助入口は維持可 | 熟練度進捗、燃料・軍需・回復予測、基本／実効射程、視界、攻撃、騒音、鎮圧、砲兵・航空・輸送 |
| 可視ゾンビ | 名前、HP | HP、攻撃、移動、射程、公開Wave所属 | 追跡ボーナス中 | 詳細 | 攻撃回数等の公開情報。追跡ルール説明はヘルプ |
| 施設 | 名前、状態、労働者または住民 | 状態、人口／上限、生産予測、給電、供給 | 停電予測、停止理由、感染、都市過密、復旧待ち | 人口操作、対象施設の給電ON/OFF、編成可能な施設の編成 | 入出力・給電の予測／実績、復旧、都市間移住、基地、ドローン、撤収等 |
| 検問所 | 名前、役割、状態 | 待機／審査／合格／感染の4数、次の到着、供給、現在／審査中方針と残り | 感染、Final後の新規到着停止、不合格見込み | 方針選択 | 維持費、拒否、方針比較、再配置、有効化、復旧 |
| 地形／道路 | 座標、地形 | 地形、道路／都市オーバーレイ、可視の有刺鉄線HP | 局所建設不可理由1行 | 合法な局所建設と有刺鉄線。多い場合は建設一覧への入口 | 地形詳細。一般的な建設・有刺鉄線ルールはヘルプ |

**P-1 全国の衛生・飢餓・感染予測**: 全国の食料／民需不足率、衛生ストレス・蓄積、飢餓死亡は内政の予測欄へ移す。全項目が正常なら`異常なし`1行とし、数値内訳は折りたたむ。表示小数は2桁まで、ストレス等の詳細内だけ3桁を許容する。施設・検問所には、その拠点の公開感染確率が正、または感染者がいる場合だけ例外を出す。非公開の感染人数を0として正常扱いしない。

**P-2 原発遠征**: 内政の先頭には状態チップ1行を残し、ルール説明をヘルプへ移す。他の既存Objectiveや期限・操作の導線を削除する根拠にはしない。

**P-3 説明の移動**: `tip*`・`muted`等の一般説明段落は、ヘルプの対応節に同じ内容があることを確認して外す。ない説明は日英のヘルプへ移してから外す。Class名だけで現在値・拒否理由・操作予測まで削除しない。

**P-4 合法性・拒否理由**: `actionReasonFor`／`localizeActionError`等の既存Core判定と日英理由を使う。施設操作や編成等の無効ボタンと理由を維持する。局所建設は現行どおり合法候補だけをボタンにし、不可能なら短い理由を示す。独自の合法性判定や全候補座標一覧を追加しない。

**P-5 操作の維持**: 編成は州都・都市・Army Base・Air Baseの全対応拠点に残す。労働者のスライダーと数値入力の同期、都市間移住の確認、給電、撤収、検問所方針・拒否・移設・有効化・復旧、有刺鉄線、砲兵の展開／収納・砲撃、航空の離着陸・搭乗／降機、IFV輸送、軍用ドローン等の既存操作を維持する。ユニットの主要操作は盤面近傍で完結する既存契約を守る。操作入口から開くFormで費用・不成立理由・移動／攻撃の予測を確認できるようにする。

### 5.5 盤面と観戦の表示（M）

**M-1 翻訳の修正**: 施設名は`facilityLabel`、ユニット名は`unitLabel`等の共通名称表を使い、存在しない`t('civilianFactory')`等のキーを画面に出さない。盤面、対象切替、パネル、警告、確認、ログの日英表示を点検する。観戦のユニットIDはM-4に従う明示的な例外であり、翻訳漏れと扱わない。

**M-2 文字**: 表示する盤面文字は画面上で11 CSS px以上となるようにし、縁取りまたは暗い半透明背景を付ける。ズームで読めない大きさへ縮むことを避ける。現行の低Zoom LODで文字を省略する規則は維持し、全ヘックスへ小さい文字を常時追加しない。通常プレイのHuman Unitの文字項目は名前・HP・Attack Charge・補給内外に限定する。

**M-3 操作UIの配置**: 補給トグル、ユニットメニュー、モード表示、確認UIは盤面内に収め、パン・ズーム・リサイズへ追随し、相互に重ならない。対象切替はS-5の固定ヘッダーに集約する。

**M-4 Replay／LiveのユニットID**: AIの認知と観戦者の理解の対応を取りやすくするため、両観戦UIでユニット名を表示する箇所には、ローカライズ名と**公開されたユニットID全文**を併記する。対象は盤面のユニット名ラベル、選択情報、同一ヘックスの対象切替、UIが生成するログ・行動表示のユニット参照。形式例は`機動隊 [riot-police-1]`。公開される味方と可視の敵の双方を対象とする。LODで名称自体を省略する場合でも、選択情報ではIDを読めること。

記録済みコメントやdecisionSummaryは原文を保ち、IDを書き換えたりAIの意図を補作したりしない。非公開ユニット、内部Target、Group ID等を追加開示しない。通常プレイへIDが漏れないよう表示コンテキストを区別する。施設等の内部キーを表示名として露出させる例外にはしない。観戦用の新しいIDや形式変更は導入しない。

### 5.6 視覚（V）

**V-1 色の意味**: 通常UIは濃淡と線を基本とする。注意は琥珀、危険は赤、良好な状態の文字は緑、Advisoryは青とする。意味のない色の枠を増やさない。既存の地形・陣営・補給等の盤面色はこのUI色整理の対象外。`:root`の変数へ意味をまとめ、触るコンポーネントの色直書きを置き換える。CSS全体の一括変更はしない。

**V-2 文字**: 読ませる文字は11px（0.6875rem）以上。0.58〜0.65remの小さいラベルを使わない。数値は`font-variant-numeric: tabular-nums`を維持する。

**V-3 レスポンシブ規則**: HUDの`max-width: 560px`・`359px`等の重複した`@media`は触る範囲で整理する。

**V-4 操作域**: ボタン・チップ・タブ等の操作域は幅・高さとも44 CSS px以上。日英の名称長に対応し、切詰めで操作先を識別できなくしない。色だけで状態を伝えない。

### 5.7 終了済みSessionのArtifact出力（R）

**R-1 公式出力**: v1.7.1で作成し、勝利または敗北（少なくとも`capitalLost`）で終了した保存済みSessionから、公式Session CLIの`artifact`コマンドで自己完結した公開Artifact ZIPを出力できること。進行中の途中記録exportも維持する。Manifest、保存された実Map、公開Decision／Event、差分・Snapshot・Payload・lineage等、既存の必要な記録を欠落させない。

**R-2 終了後の進行禁止**: Move・攻撃・EndTurn等は引き続き拒否する。すべての`gameOver`ガードを一括で外さず、保存復元を公開Agent／Bridge APIへ無条件に開放しない。

**R-3 非改変**: 出力は参照操作であり、元Session、既存保存、RNG、Revision、公開履歴、拒否記録を変更しない。既存出力の上書き拒否と途中失敗時の扱いも維持する。

**R-4 検証・公開境界**: 版・構造・不変条件・復元後の公開状態照合を省略しない。Private Stateや非公開情報、外部Session依存をZIPへ混入させない。

**R-5 再現と修正方針**: 推定原因は、`restorePrivateSessionState`が終了済みsnapshotから作ったEngineへ再び`LoadSnapshot`を渡し、`step`先頭の`gameOver`ガードで拒否される経路である。実装前に、実行対象版と整合する終了済みfixtureを用意し、公式出力経路が**版不一致ではなく対象の`game_over`によって失敗すること**を確認する。修正前後で同じ入力を使う。v1.7.0の元Session救済や同じ710決定の再プレイは要求しない。

読み取り用の検証・復元経路を整理する、または公開記録から必要な整合性保証を保って出力する方法から、再現結果に基づき選ぶ。Coreのガードや公開API契約へ影響する場合は親が設計を判断する。終了済み復元の許可と進行操作の許可を分離する。

**R-6 必須検証**: Reader、Coreによる決定列再実行、ブラウザGUI観戦をすべて必須とする。§8.4の勝利・敗北の限定fixtureで行い、一方の成功で他方を代用しない。元のv1.7.0 Sessionは今回の受入対象外として記録し、未確認を成功に数えない。

## 6. 不変条件

- ゲームルール、GameActionの合法性、ゲーム状態変更経路を維持する。
- 視界外の敵や非公開情報を、選択候補・危機欄・観戦IDから追加開示しない。
- EndTurn確認のCritical、未使用Attack Charge、自動鎮圧、確定敗北見込み、飛行中航空機等の既存条件を維持する。
- 新規ゲーム・ロード時のUI初期化、初回ガイドを維持する。保存互換・保存保全は§1.5に従う。
- 盤面アセット、描画順、LODは文字と明示したUI表示の変更以外を維持する。
- 電力HUDの需要／供給表記、Tooltip、アクセシブル名、不足条件を維持する。
- UIを減らすためにAgent API、Observation、Query、Replay記録の情報やIDを削らない。

## 7. 実装フェーズ

単独作業を前提とする。RはUIと独立に進められるが、版変更・共有描画・テスト・文書の統合箇所を確認し、「絶対にファイルが重ならない」と仮定しない。Rを先に行うことを推奨する。各フェーズで変更箇所のテストと型検査を行い、最終段階で§8を満たす。分割は差分をレビューしやすくする目安であり、コミット・push・公開を本書だけで依頼するものではない。

## 8. 試験・受入条件

### 8.1 自動テスト

- **選択**: 主要対象が複数なら安定順で循環、1個なら解除。可視ゾンビ・地形から主要対象への再タップ、主要対象0個の解除。固定ヘッダーから施設＋ゾンビ、ユニット＋地形、道路等の全公開候補へ到達する。視界外・破壊済み・搭乗中ユニットは含めない。
- **モードと操作**: 移動・攻撃・確認・配置中の既存動作を維持。内政で選択表示を隠し、作戦図で復帰。消滅・視界外等なら解除。内政で盤面を選ぶと先頭選択して作戦図へ戻る。途中操作を復帰しない。
- **上部**: 感染0、警告0、最終襲撃前、正常保存では不要なチップが出ない。必要な資源等の0は残る。不足資源だけが警告になる。幅不足時の優先、ほかN件の数、各入口と危機全件への到達、重ね表示の排他と閉じ方を検証する。
- **シート・ビューモデル**: 3状態の内容差、最大5要点、条件付き例外、全国予測の正常時1行、必要な詳細だけの展開、操作Formの排他、対象切替時の初期化。要素数だけで実寸の収まりを合格にしない。
- **既存操作**: P-5の操作が到達可能で、実行や無効理由がCoreと一致する。労働者スライダーと数値入力、移住確認、編成可能な全拠点を含む。
- **日英・ID**: 通常プレイの盤面・標準／詳細・ログ・警告・確認に生IDや翻訳キーが出ない。Replay／Liveでは名前と公開ユニットIDが一致し、Hiddenな対象を出さない。表示切替の前後でState・RNG・記録のIDが変わらない。
- **版境界**: v1.7.1のSave・Session・Checkpoint・Replay／Artifactが対応経路で使えること、1.7.0以前を理由付きで非破壊拒否すること。新規通常ゲームの保存とAI／観戦の保存領域が混ざらないこと。
- 既存のController・Board・Asset・Action等のテストは変更要件に対応する期待値だけを更新する。翻訳不具合も修正前後比較を行い、できなかった場合はその限界を記録する。

### 8.2 ブラウザでの確認

既存のPlaywright手段を使い、390×844、360×740、1280×720の**日本語と英語**でスクリーンショットと実寸を記録する。ブラウザのViewport確認と実機試験を区別する。

通常プレイの必須状態:

1. 新規ゲーム直後の未選択。
2. ユニットの標準・折りたたみ・展開、詳細の個別開閉、主要操作と確認。
3. 同一ヘックスの再タップと固定ヘッダー選択。施設＋可視ゾンビ、主要対象1個＋地形、地上／航空の重なりを含む。
4. 各施設種別。労働者・住民・給電・編成・停電予測・無効理由がある場合を含む。
5. 検問所の方針と操作、空き道路の建設。
6. 地形の建設可／不可、有刺鉄線、複数建設候補への入口。
7. 内政の概況、以前の選択復帰、盤面タップでの作戦図復帰。
8. 警告、感染、保存失敗等の同時出現と「ほかN件」、人口・資源・Hordeの重ね表示。
9. 最終襲撃後の勝利進捗と警告の同時出現。

**390×844の必須数値**: `.board-region`の高さ／`#app`の高さを測り、未選択の既定で55%以上、ユニット選択の標準で45%以上。盤面より上のレイアウト上の帯は合計140 CSS px以下、最大3段。重ね表示・手動で開いた詳細・確認ダイアログを閉じた既定状態で測定し、比率を達成するために透明な要素で盤面を覆わない。状況チップが多い状態も上部の高さ条件を維持する。

**全画面サイズの必須条件**: 文字11px以上、操作域44px以上、横方向のはみ出しなし、操作UIの重なりなし、必要な情報・操作への到達、ブラウザ警告・エラー0件。360×740とPCでは同じ盤面比率や140px上限を必須としない。390×844の標準内容はB-2を満たす。数値を黙って下げず、未達なら原因と実測を記録して解決する。

Replay／Liveは画面構成の刷新を行わず、同じ3サイズ・日英で共有ラベルの可読性、公開ユニットIDと名称の対応、選択・ログ、非公開対象の非表示を確認する。Replayの出力ZIPからの観戦確認は§8.4と兼ねてよい。

### 8.3 回帰範囲

- 必須: `npm run typecheck`、`npm run build`、UI全テスト、変更したReplay／Live・互換判定・Agent／Sessionのテスト、§8.2と§8.4。
- Rと版境界を含む横断変更のため、最終統合差分で`npm test`全体を1回成功させる。途中のR完了時に全体試験が必要なら行ってよいが、同一差分の成功済み全体試験を根拠なく繰り返さない。
- 長時間のRandom／Balanced等のシミュレーションは今回の必須範囲に含めない。既存のv1.7.0受入記録やリモート未確認を今回の成功として流用しない。
- ユーザー指定により、時間のかかるGitHub Workflowは起動確認までとし、結果確認・監視を行わない。結果は後日のユーザー依頼で確認する。ローカル必須検証とリモート未確認を分け、Workflowの起動を成功・完了として扱わない。

### 8.4 不具合修正の必須受入

以下はすべて必須。実装対象版に整合した、保存・再ロード可能で決定列を再実行できる勝利／敗北の限定fixtureを使う。実際のCore・Session・Readerを通し、対象機能そのものをモック化しない。Windows上の公式CLI出力と、ブラウザのPC／モバイルViewport観戦を確認し、実行環境・入力・結果を記録する。

| 観点 | 合格条件 |
| --- | --- |
| 修正前後の再現 | 同じ終了済み入力から公式出力経路が修正前は対象の`game_over`で失敗し、修正後は成功。版不一致・fixture破損の失敗で代用しない |
| 勝利・敗北 | 勝利と少なくとも`capitalLost`の敗北を出力し、結果・Turn・gameOver・決定数・集計が保存記録と一致 |
| 進行中と新プロセス | 途中export成功後もプレイ可能。保存し直した終了状態、新しいCLIプロセスからも出力可能 |
| Reader | 公式出力ZIPを`SessionService.readArtifact`と`ReplayPackage.open()`で読み、hash・Payload・最終状態・先頭／中間／最終seekを照合 |
| Core再実行 | 同じ初期条件・決定列をCoreで再実行し、各stepのstate digest／Eventと最終Resultが一致。Reader成功と別に記録 |
| GUI観戦 | 公式出力ZIPをブラウザから読み、再生・先頭／中間／最終seek・終了表示・通常ゲーム保存の保全を確認。M-4の公開ユニットIDも照合 |
| 終了後進行禁止 | 終了済みゲームへのMove・攻撃・EndTurn等を拒否し、盤面・Turn・資源・RNGを進めない |
| 非改変・出力保全 | export前後の永続保存ファイル内容／hash、Revision、RNG、公開履歴・拒否記録を比較。既存出力の上書き拒否と失敗時の保全も確認 |
| 拒否操作の保持 | 受理・拒否双方を含む決定列で、拒否理由・順序・hash chain・最終集計を欠落／改変しない。710決定という元報告の件数自体は必須にしない |
| 不正データと公開境界 | 破損hash、欠損Payload、未知／非対応版を理由付きで非破壊拒否。ZIPにPrivate State・非公開情報を含めない |
