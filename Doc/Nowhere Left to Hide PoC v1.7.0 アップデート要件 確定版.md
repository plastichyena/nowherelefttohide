v1.7.0は、既存の固定マップを保持してランダムマップを追加し、AI向けの情報・操作説明・公開APIを改善する。本文の必須条件と採用したAI改善はすべてリリース必須である。

今回の作業は文書作成・配置整理・Gitへの記録とpushまで。ゲーム実装、依存導入、ゲーム検証、リリースは別工程である。サブエージェントは使用しない。

### 1.1 調整可能な値と固定条件

- 「初期案」「調整可能」と明記した数値は、実装担当が検証に基づき確定要件の範囲内で決定する。採用値・理由・測定条件を記録し、受入検証前に固定する。通常の数値決定に追加承認は不要。
- 受入結果を見て同じ生成版の閾値を黙って変更しない。値を変えた場合は設定・生成版を更新し、影響する検証を再実施する。
- 必須条件やゲームルールの変更が必要ならユーザーへ確認する。密集制限・方面別quotaなど、不採用とした制約を品質調整の名目で再導入しない。
- 全seed同難易度・必勝・敵を含めた期限達成は保証しない。地図の成立性と実プレイの成績を分けて評価する。

### 3.3 配置品質

- 全恒久施設の下地はplain。施設同士の同一Hex重複・Reserve配置を禁止する。

- 施設の密集に専用制約を設けない。Gas爆風対策の最小施設間距離や隣接数制限を追加しない。
- 中立施設の東西南北ごとの数量quotaを設けない。到達・供給・期限条件を満たす偏りを許容する。
- 重要施設の州都からのHex距離は、Army6～9、Air7～10、原発12～18、油田10～18を初期案とする。MP・Fuel・供給・期限の検証で調整可能とし、性能・報酬・期限は変えない。敵を除いた合法手順で、地形だけで期限達成が不可能な配置を排除する。

## 4. 地形・河川・道路

架空のUNA内陸地域として、平原主体、まとまった森林帯、少数の連続した山地、河川・湖を生成する。海・湾はランダムモードには生成しない。固定モードの湾は維持する。既存のplain / forest / mountain / waterと道路・橋・Urbanを使い、新たな地形ルール、渡河Action、橋破壊、船舶、標高戦闘補正は追加しない。

河川はwater Hexの6近傍連続列とし、源流・合流・流出口または湖への接続が整合すること。途中で消える川、無限循環、意図しない孤立水面を防ぐ。川を道路工事で無差別にplainへ変えず、橋で交差する。

**川によって分かれた地域には複数の渡河経路を確保する。** 同じ橋を共用する2経路は複数経路として数えない。地上移動グラフ上で、一つの橋の通行だけに依存して接続される地域を作らない。これは地理検証上の条件であり、橋破壊機能を追加するものではない。

支線・アクセス道路は施設の生成位置へ接続し、6近傍ごとの接続を保証する。これらの道路を5本目以降の到着方面や検問所幹線にしない。移動上の道路判定は幹線とcollector/accessの両方を含む。

地形割合の初期目標はplain55～75%、forest15～30%、mountain5～15%、water2～8%。分母は全2,601 Hex、overlay下の地形を数え、合計100%の同時条件とする。割合は検証で調整可能。最大連続成分・孤立成分・河川接続・橋数・道路長・移動MP/Fuel・修復量を測定し、連続性と遊びやすさを確認する。

生成は、固定位置予約→地形／水系→固定幹線の橋→施設→接続路→構造／供給／到達／序盤成立性の検証を基本とする。詳細アルゴリズムは実装担当が決める。候補・修復順を決定的にし、保護条件を満たすための大量の地形削除を避けるため修復量の上限を設定・記録する。

## 5. seed・生成失敗・カスタム設定

### 5.1 seedと再現性

- 通常UIはseed入力1個。API・詳細設定はmapSeedとgameplaySeedを個別指定可能とし、省略した側には通常のrootSeedを使う。
- 同一の地図用seed・シナリオ・有効な地図関連設定・生成版から同じ静的地図を得る。gameplaySeedだけを変えても地形・施設座標・道路は変わらない。
- カスタムの地図関連Configも再現条件に含める。同seedでもConfigを変えれば地図が変わり得る。初期敵・中立人口等の抽選結果は静的な公開地図と分離する。
- map内はterrain / hydrology / layout / roads等、gameplayはinit / mainおよび既存の感染・砲撃等のdomainを分離する。地図の失敗試行や修復でgameplay RNGを消費しない。
- 固定モードの標準seed指定はlegacy初期化を再現する。個別seedを指定する経路も役割と処理順を定義し、両seedが従来seedと同値のときに既存の結果を保つ。
- seedは現行の安全な整数の受理範囲を維持する。0・負数・2^32近傍・safe integer境界を明文化し、NaN・Infinity・小数・危険整数は拒否する。異なるseedが必ず異なる地図になることは保証しない。
- 「ランダムseed」操作はUI境界で値を1回決め、表示してCoreへ渡す。生成中に時刻・Math.random・処理時間・並列完了順で結果を選ばない。
- domain導出・文字列エンコード・丸め・overflow・同コスト時の順序を版管理し、テストベクトルを用意する。Windows/LinuxのNodeと対応ブラウザで同じ地図hashを得る。

### 5.2 地図生成失敗と代替

最大64試行を初期案とし、実装時に検証して上限を固定する。seed・生成版・設定・attempt・domainから試行を決め、最初の有効地図を採用する。時間制限で採用地図を変えない。

上限まで成立しなければ、**ランダムモード用の専用代替マップ**を使う。現行固定マップへの切替は行わない。代替も、固定骨格、内陸地形、施設構成、全施設の到達／供給、複数渡河経路等の必須条件を満たす。代替の静的配置は事前に検証・版管理する。seedごとの配置多様性は通常生成に対する条件とする。

代替利用を人間向け画面・開始応答に明示し、使用理由、試行数、代替ID／版、実体／hashを保存する。同じ開始条件では代替の選択も再現する。

**標準UNAの受入生成テストにおける代替率は10%以下。** 分母は事前登録した通常の生成品質評価群の全件、分子は再試行上限後に代替を採用した件数。内部の1試行ごとの棄却率とは別である。強制失敗・不正入力テストは専用群として別集計し、通常群の失敗seedを除外しない。件数の調整で既知の失敗だけを除かない。カスタム設定は別集計とする。10%は本作の採用目標であり、業界標準値とは扱わない。

### 5.3 初期敵配置の失敗

標準UNAの初期敵はNormal40 / Hunter4 / Gas4 / Screamer2の計50体。現行の安全距離（Normal8以上、Hunter20以上、Gas9以上等）、通行・非重複・Reserve除外、各敵から両軍事基地が見えない条件を維持する。道路からの離隔の優先と、現行で許された候補不足時の段階的緩和は現行規則の範囲内とし、安全距離の短縮や敵数削減を新設しない。

地図確定後にgameplay側で初期敵を配置する。成立しなければ、上限付きの決定的手順で敵配置だけを再試行する。上限・導出手順は実装時に版管理する。それでも成立しなければ、原因を返して開始を拒否する。**地図を再生成したり、代替へ切り替えたりしない。** 現在のゲーム・保存を維持し、初期敵の隠された座標を公開診断に漏らさない。

標準の受入群では、代替を含めた開始不能や初期敵配置失敗がないことを確認する。ただし有限の試験で全seedの成功を証明したとはしない。

### 5.4 カスタム設定とUI補正

標準UNAは第3章の値を固定する。カスタムでは既存の変更可能項目について明示設定を優先し、初期資源・人数・性能等を変更できる。施設数・州都・検問所・幹線・初期Humanの配置骨格は共通とする。UNAの110人等をすべてのcustomに強制しない。初期供給半径を変える場合の施設内外構成は、実効Configと実供給判定で検証する。

設定型として不正な入力は拒否する。設定として有効でも配置条件と両立しない場合は、通常生成・代替の成立可否を検証する。人間向けUIでは次の手順を使う。

1. 成立しない理由と、地図・初期配置の成立に必要な最小範囲の補正案を表示する。補正前／後の値と理由を項目ごとに示す。
2. 対象は初期供給半径・初期配置人数などの該当項目に限定する。資源量・戦闘性能・生産性能・報酬・期限・固定配置骨格は補正しない。補正可能項目の明示リストを実装時に作る。
3. ユーザーが補正を確認・承認した場合だけ、補正後Configを再検証して開始する。未承認・キャンセルでは現在のゲームを変えない。補正後の実効設定を保存・再現条件に含める。
4. 許可範囲の補正で成立しなければ開始拒否。初期敵配置失敗時も元Configの敵数・安全距離を暗黙変更して再試行しない。別の設定としてやり直す場合だけ上記の明示確認を使う。

**API・CLIでは補正を行わない。** 成立しない理由を返して拒否し、呼出側が設定を修正して再要求する。Bridge/Session等の非対話入口も同様とする。

## 6. UI・保存・公開境界

### 6.1 人間向けUI

ランダムを初期選択とし、固定への切替、通常seed、個別seed詳細設定、再現キーのコピー、生成エラー、代替利用表示を用意する。日英UIとヘルプを整備し、タイトルは日本語UIでもNowhere Left to Hideとする。

**視覚的なプログレスバー・処理段階・試行回数・キャンセルを必須**とする。総作業量が未確定の間は動作中を示すアニメーションを使い、根拠のない全体完了率や残り秒数を表示しない。地形・道路・施設・検証等の段階を示す。UIが更新・キャンセルできる実行方式を採り、生成がメインスレッドを塞いでバーが止まる設計にしない。

秒数による性能合否上限は設けない。通常成功・代替・キャンセルそれぞれの時間、p50/p95/max、環境を記録する。試行回数で処理を有限にする。キャンセル済み生成の遅延完了によってゲームを置換しない。開始成功の確定までは旧ゲーム・保存を保持する。

PCおよび390×844で開始・詳細設定・補正確認・進捗・キャンセル・日英表示を操作可能とする。AI応答に人間向け導入文や装飾を混ぜない。

### 6.2 保存・互換性

- **過去版のSave・Session・Checkpoint・公開Artifact／Replayは非対応**。元データ・現ゲーム・保存枠を変えず拒否し、非対応版を表示する。旧版reader・自動移行・converterは追加しない。
- v1.7.0の両modeは、Map実体＋再現descriptor＋実効Config＋必要なRNG状態を保存する。load時に最新generatorで生成し直さない。
- descriptorはscenario、mode、root/map/gameplay seed、generator ID／版、設定ID／実体、attempt、代替利用／ID／版、Map hash、Config版、Buildを特定できる情報を持つ。初期敵配置の再試行情報もprivate再現情報として保持する。
- 初期静的Mapと、建設や移動を反映した現在状態を区別する。未知版、破損hash、不正道路／座標／構成、Configとの不整合は状態不変で拒否する。
- 固定canonical検証とランダム構造／descriptor検証を分け、固定validatorを弱めて通さない。hash一致だけで構造の合法性を保証しない。
- v1.7.0の公開観戦はMapと公開frame/deltaを同梱し、先頭・中間・最終seekを検証する。ActionをCoreで再実行する検証は別に行い、観戦seek成功で代替しない。

### 6.3 公開境界・版

公開Observation・Compact・Query・Handoff・終了報告はmode・再現条件・Map識別子を必要な範囲で保持する。公開Map hashは公開静的投影だけから作り、初期敵座標・非公開人口・PRNG snapshot・未確定Waveを含めない。完全状態hashと内部診断はprivate検証へ分離する。seedが公開でも新たなHidden開示を認めるものではない。

キャッシュはMap系列IDだけで共有しない。同seed別Config／設定、mode切替、保存復帰、代替利用で混線しないようMap実体・内容を識別する。

Appは1.7.0。Rules / State / Config / Save / Agent / Observation / Bridge / Artifact / Session / Checkpoint / Action / Query / Summary等の版番号は実装差分に基づいて更新し、単一の出典で管理する。ドラフトの仮番号を無条件採用しない。固定Map IDは既存契約を維持する限りfixed-51x51-v9を保ち、ランダム系列・generator・設定・代替の版を別に管理する。

### 7.1 根拠の限界

元ドラフトのSol初回T32敗北・リベンジT79敗北等は受領報告であり、本作業で元ログ・ZIPを再実行した結果ではない。再現確認済みの新規エンジンbugがあるとは扱わない。IFVの予測HP/Fuel一致時の停止も、当該要求のexpectations実体未照合のため「未指定だった」と断定しない。

実装時は条件を絞ったfixtureで確認し、バグ修正なら修正前の失敗と修正後の成功を同じ入力で確認する。説明改善と動作bugを分け、報告された敗北を技術的失敗やモデル性能差の証明にしない。外部ログが入手できなくても、代替fixtureの範囲と元ログ未確認を記録し、元プレイ再現成功とは主張しない。

### 9.3 大量生成・自動プレイ・性能

初期計画はCI seed1～100＋境界／既知失敗fixture、リリース前seed1～10,000＋事前固定した散在seed1,000件、目視32マップ。件数は実行時間を測って調整できるが、理由・実施件数・除外を記録し、境界と既知不具合ケースを省略しない。

各seedの生成版・設定hash・attempt・棄却理由・通常／代替・Map hash・地形比／成分・橋／道路・建設余地・施設距離／方面分布・主要MP/Fuel・時間・メモリ・終端結果を記録する。方面分布・密集は観測値であり、採用しなかったquotaや密集制限の合否には使わない。採用された全地図でhard invariant違反0、標準通常群の代替率10%以下、最終生成不能／初期化失敗0を確認する。

**自動プレイ評価は必須。** 初期案はrandom100 mapSeed×gameplaySeed3個×Random/Balancedの2方策＝600ゲーム。件数は実行時間で調整し、群・Rules・Agent版・設定・打切りTurnを事前固定する。固定モードの比較群は別集計する。勝敗、到達Turn、期限施設の到達／確保、人口・資源・kill/loss、技術失敗、未終局打切りを分ける。打切りを敗北／成功に数えず、勝率向上を合格条件にしない。

地形起因の序盤不成立、入口ごとの経路差、橋依存を確認し、問題を敵弱体化・IFV強化・Wave変更で隠さない。ゲーム評価で必須条件違反を発見した場合は修正し、影響範囲を再検証する。外部LLM長期プレイは必須ではなく、行う場合は初見・memory・反省ありを区別する。

生成の秒数による受入上限は設けず、実測p50/p95/max等を記録する。試験のハング検出を通常の代替選択に使わない。各実行の未実施・失敗・skip・結果未確認を成功と分ける。
