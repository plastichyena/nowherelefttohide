# Nowhere Left to Hide PoC v1.5.5 アップデート要件 ドラフト

- ステータス: 検討用ドラフト・未実装
- 作成日: 2026-09-08
- 基準: `Nowhere Left to Hide PoC 現行仕様.md`（v1.5.4）
- 参考: `output/claude-playtest-20260908/REPORT.md`。プレイの自己評価は仕様の正本とせず、現行仕様・実装と照合して扱う。

本書は次期更新の検討資料である。現行仕様は実装・テスト・動作確認が完了するまでv1.5.4のまま維持する。本書の確定後に実装し、完了した要件を現行仕様へ反映する。

## 1. 目的と対象範囲

AIの判断に必要な公開情報の提示を改善し、AIのプレイをコメント付きで観戦できるようにする。固定マップに施設を結ぶ接続道路を追加し、仮設住宅の採用価値を高める。

### 1.1 ユーザー判断として確定した範囲

- 対象Versionはv1.5.5。
- AI向け情報開示を改善する。
- AIリプレイのプレイヤー向け視覚再生を追加する。簡潔な意思決定コメントの表示を目指し、主用途はエンターテインメントとする。
- 幹線道路以外に施設を結ぶ道路網を追加する。道路の直接的なゲーム効果は移動MPコストのみとする。
- 仮設住宅の建設費を50から25 Civilian Goodsへ変更する。
- 仮設住宅はソフトキャップ内の住民について1人あたり0.5 Civilian Goodsを生産し、端数を切り捨てる。
- ランダム生成マップは含めない。
- Zombieの能力値強化は見送る。

### 1.2 本書での推奨案

以降の詳細は、上記範囲を実装可能な形にするための推奨仕様である。特に末尾の未確定事項は、確定版で判断を記録する。

- 固定マップのサイズ・州都・施設配置・幹線支線数・Wave体系を維持する。
- リプレイは公開記録を再生する読み取り専用モードとする。
- 住宅生産は健常住民を対象とし、正常稼働・補給内・給電中に限る。
- 改善したAI情報、住宅、道路を段階的に検証し、難度変化の原因を分離する。

## 2. AI向け情報開示

### 2.1 共通原則

- 公開Observationから導出できる情報を、判断する対象と同じ場所へまとめる。
- Compactは反復判断に必要な小さな要約を持ち、施設別・Action別の詳細はQueryで取得する。
- Hidden Enemy、内部Target、将来乱数、拒絶Counter等の非公開境界は維持する。
- 確定結果、条件付き結果、未計算の結果を区別する。公開情報だけでは確定しない将来の敵行動を保証として出さない。
- UIとAIで共通のCore Queryを利用し、予測用のルールを別実装しない。
- フィールド名は実装時に確定する。以下の項目名は意味上の要件である。

### 2.2 維持人口と資源収支

CompactのEndTurn予測に以下を追加する。

- 維持人口の内訳: 都市・住宅住民、生産施設等の労働者、部隊人口、Checkpoint健常Queue。
- Queueはwaiting / screening / approvedを区別し、維持対象外の感染者と混同しない。
- Food / Civilian Goodsの基本維持費、過密追加費、住宅停電追加費、合計維持費。
- Civilian Goodsの生産、軍需工場投入、維持消費を分離した収支。
- 給電不足・感染・復旧待ち等の主な生産停止原因と詳細Queryへの導線。

「維持可能人口＝Civilian Goods生産量」という無条件の人口上限は表示しない。人口配置、過密、電力、投入資源に依存するため、現在の構成の予測収支を正本にする。

### 2.3 Gas Zombieの攻撃プレビュー

- 直接攻撃による撃破時に起きる死亡爆発について、影響する隣接Hexを示す。
- 公開範囲のUnitについて、地形軽減・残HPを反映した被害と死亡見込みを示す。
- 公開Facility / Checkpointについて、予測感染数、健常人口0への到達、陥落・停止への影響を示す。
- 爆発による敵への利益と、自軍への損失を同じプレビューで示す。
- 公開情報で求められる連鎖と、隠蔽情報のため確定できない範囲を区別する。隠蔽個体の存在を示すフラグは出さない。
- 非致死攻撃では即時爆発が発生しないことを区別する。
- 敵フェーズの追跡・迎撃・反撃による将来爆発を、この即時プレビューの確定結果に含めない。

### 2.4 施設復旧・防御の説明

- ruined / disabled等の状態とは別に、施設種別に応じた復旧可否を示す。
- 奪還、感染鎮圧、敵排除、復旧待ち等、現在不足している条件を示す。
- 復旧開始前の日時nullと、回復不能を区別する。
- 生産再開には別途人口・補給・電力等が必要な場合、それを奪還と区別する。
- 地形防御の理由と倍率が一致することを確認し、Urban Overlayを施設・Checkpointと対応付けて説明する。

### 2.5 Action契約と候補検索

- `PLAY_WITH_AI.md`と機械可読API情報に、主要Actionの必須フィールド・例・対象条件を示す。
- Move / Attack / AssignWorkers / TransferPopulation / SetCheckpointPolicy / TurnAwayCheckpointRefugees等を対象にする。
- TransferPopulationはCoreで許可される任意整数人数をAgent APIからも指定可能にする。
- 大量の人数別Actionを列挙する方式は避け、対象組と人数範囲・制約を公開する。既存の列挙型APIとの整合方式は確定時に定める。
- 人数・対象資格・ターン開始Snapshot・Action予算は既存Core検証を使用し、不正Actionの状態不変を維持する。
- 建設候補を支線・施設種別等で絞り込めるようにし、Checkpointの補給差分へ全候補取得なしで到達できるようにする。
- Turn Awayはwaitingのみが対象であること、退去可能人数、対応する維持費減少を示す。全Queueを退去可能と誤認させない。
- Normal / Strictの審査拒否とTurn Awayのどれも将来Wave強化に関係し得ることを説明する。正確な非公開CounterやBonus計算状態は公開しない。

### 2.6 実行確認

- 既存play-turnの実行済み・拒否・未実行の結果を推奨経路にする。
- バッチ停止後は未実行Actionを適用済みとして扱わないことを文書化する。
- 受理された結果のRevisionと観測された状態を確認する例を載せる。

## 3. コメント付き観戦リプレイ

### 3.1 再生方式

- 公開Artifact内の記録済みObservation / Action / Event / decisionSummaryを再生する。
- 現在のGameEngineで旧Action列を実行し直す方式を、観戦の必須条件にしない。
- 検証用の決定的Replayと、プレイヤー向け観戦再生を区別する。
- 通常ゲームのState、autosave、進行中Sessionを変更しない。
- FoWはその時点でAIに公開された情報に従う。全知視点は追加しない。

### 3.2 v1.5.5の基本操作

- 公開Artifactを読み込んで再生開始できる。
- 再生・一時停止・速度変更・前後のDecisionへの移動・ターン指定移動を提供する。
- 現在Turn、Decision、行動主体、Action、結果を表示する。
- 攻撃・撃破・施設陥落・Wave到来等の重要Eventを盤面とログで識別できる。
- コメント表示、盤面操作、ログ閲覧がモバイル画面で両立する。
- 移動を補間表示する場合も、記録にない経路や敵移動を推測して事実として再生しない。
- 長いEndTurn内に公開Eventが複数ある場合、盤面の中間状態を復元できる範囲と、Eventログだけの範囲を区別する。

### 3.3 意思決定コメント

- 既存decisionSummaryを利用する。非公開の詳細な思考過程は収集しない。
- 判断直前の公開盤面でコメントを提示し、その後に行動と結果を表示する。
- 「AIの判断コメント」と「ゲームの結果ログ」を区別し、AIの誤認を仕様説明として表示しない。
- コメントがない記録でも再生可能とし、後付けでAIの意図を捏造しない。
- 拒否されたActionは状態を進めず、拒否理由を表示する。未実行計画は実行履歴へ追加しない。
- コメントは通常テキストとして表示し、HTML等として実行しない。
- AIプレイ用文書に、短い目的・判断根拠を記す推奨例を追加する。

### 3.4 読込・互換性・性能

- v1.5.5で作成した公開Artifactを必須対応とする。
- 推奨追加範囲としてv1.5.4の公開Artifact Schema 10.0.0を観戦専用で読み込む。通常Saveの移行とは分離する。
- 現在のArtifact Packageは複数ファイルを含むため、ブラウザへ取り込む形式を確定する。単一ファイル配布を推奨するが、具体的なコンテナ形式は未確定。
- 欠損、破損、未対応Versionは読込理由を表示して停止し、通常ゲームへ影響させない。
- 全履歴を全Observation配列へ一括展開する前提にしない。索引・必要範囲の展開・キャッシュ上限を設ける。
- シーク時もコメント・盤面・結果の対応を維持する。分岐Sessionの履歴はArtifactのlineageに従う。

### 3.5 今回含めないもの

- 音声実況、動画書き出し、SNS投稿、オンライン共有基盤。
- 自動ハイライト編集、高度な演出カメラ、全知視点。
- リプレイ途中から通常ゲームを開始する機能。

## 4. 固定マップの施設間接続道路

### 4.1 基本

- 既存の4幹線とは別に、恒久施設を結ぶ接続道路網を固定マップへ追加する。
- 施設の位置・種類・初期人口とマップサイズは変更しない。
- Seedで配置されるArmy Baseを道路接続対象へ含める方法は未確定事項とする。
- Playerが後から建設する施設への道路自動敷設は今回含めない。
- 幹線と接続道路を視覚的に区別し、接続方向をHex上で読めるようにする。

### 4.2 効果と境界

- 接続道路の移動コストは1とする。推奨案としてHuman / Zombie双方に適用する。
- 基礎地形は保持し、地形防御・LOSへの独立した効果を追加しない。
- Urban防御を付与しない。
- Supply Source、Supply Sector、支線所属、Checkpoint配置資格、避難民入口、Wave入口を追加・変更しない。
- 接続道路という理由だけで建設資格を変えない。Plain / Supply等の既存条件を適用する。
- 幹線用の判定と移動用道路判定を分離し、既存roadフラグの用途を一括置換しない。
- Player通行禁止のSpawn Reserveや水域の通行禁止を道路で解除しない。
- 燃料消費式は変更しない。ただし経路変更で実移動距離・消費量が変わることは許容する。

### 4.3 配置と検証

- 地図案として接続経路を可視化し、確定版で座標または決定的な生成手順を記録する。
- 平地では既存MP1と同じであり、主に景観効果になることを前提とする。
- 森・山の道路では敵味方の到達時間が変わるため、Wave接触時期とHunterの到達範囲を確認する。
- 幹線との交差や施設上の道路でも、Checkpoint・施設・Unit選択を阻害しない。

## 5. Temporary Housing調整

| 項目 | v1.5.4 | v1.5.5案 |
| --- | --- | --- |
| 建設費 | Civilian Goods 50 | Civilian Goods 25 |
| Soft Capacity | 10 | 10 |
| 電力需要 | 5 | 5 |
| 民需品生産 | なし | 下記条件で健常住民×0.5、切り捨て |
| 建設上限 | なし | なし |

生産式は施設ごとに以下とする。

```text
対象人数 = min(健常住民数, Soft Capacity)
Civilian Goods生産 = floor(対象人数 × 0.5)
```

- 正常稼働・Supply内・給電中のみ生産する。
- 感染者、Soft Capacity超過人口は生産人数へ含めない。
- 端数切捨ては住宅ごとに実施し、複数住宅の端数を合算しない。
- 0人・1人は0、2人は1、9人は4、10人以上は最大5とする。
- 建設Turnは生産せず、完成後に条件を満たす経済処理から生産する。
- 既存の感染による生産停止条件に従い、健常者が残るだけで稼働可能とみなさない。
- 当ターン生産を当ターンの維持費へ使用する既存順序に統合する。
- 電力順位、停電追加維持費、自動受入順、通常維持費、過密、感染時消滅、撤去条件は変更しない。
- 生産量・停止理由・定格上限をForecast、Production Capacity、UI、AI、ヘルプへ反映する。
- 住宅の建設数、居住人数の推移、民需品生産量、停電ターン等を観測できる公開Metricsを追加する。人数の時点値と累積人ターンは区別する。

満員住宅は通常維持費10に対して民需品5を生産する。食料と電力を別途必要とし、民需工場を置き換える自給施設とはしない。

## 6. Version・保存・公開データ

- App Versionをv1.5.5とする。
- 道路・住宅変更に対応するGame Rules / Map契約と、必要なAgent API / Observation / Artifact / Save / Session契約を確認する。
- 具体的なVersion番号、旧通常Save・Sessionの受入可否は確定版で列挙する。現段階で互換を保証しない。
- 旧Artifactの観戦専用読込は、旧Saveの実行・旧Session再開とは別の互換契約とする。
- 道路と実効移動情報を公開マップ・保存・Artifactで一致させる。
- Artifactに保存された盤面を使い、旧記録へ現行マップの道路やルールを黙って適用しない。
- 互換性エラー時に旧データ、進行中State、autosaveを上書きしない。

## 7. 実装・検証の段階

1. AI情報開示と住宅変更を、既存固定マップで検証する。
2. 幹線と接続道路の責務を分離し、配置案を確定して経路・補給・建設への影響を検証する。
3. 公開Artifact読込と観戦画面を実装し、コメント・盤面・Eventの同期を検証する。
4. 統合プレイ、保存・Session・Artifact、PC・モバイル表示を確認する。
5. 確定要件との整合を確認して現行仕様へ反映する。比較不要となった要件はプロジェクトの文書整理手順に従う。

Zombieの能力値、Wave構成、回復率、地形防御倍率は今回変更しない。道路追加による間接的な難度変化は別途測定する。

## 8. 受入条件

- AIがCompactから維持費内訳を確認でき、Queryとの数値が一致する。
- Gas即時プレビューが公開範囲の実結果と一致し、隠蔽情報を漏らさない。
- 復旧可能性と稼働再開条件を区別して取得できる。
- Agent APIから合法な任意整数の人口移送が可能で、不正Actionは状態を変えない。
- 候補絞込・Pagination・Revisionの整合を維持する。
- 住宅の人数0 / 1 / 2 / 9 / 10 / 超過、停電、感染、Supply外、完成時について生産・予測が一致する。
- 接続道路でMPだけが意図どおり変わり、補給・Checkpoint資格・防御等に意図しない変更がない。
- 同Seed・同Action列のv1.5.5内で決定性、Save Round Trip、Session再開、検証Replayが一致する。
- 観戦の前後移動・ターン移動・速度変更で盤面、コメント、結果がずれない。
- 欠損コメント、拒否Action、分岐履歴、大容量記録、破損記録を処理できる。
- 旧版観戦対応を採用した場合、Claudeのv1.5.4 Artifactを実例として再生確認する。
- PCとモバイル相当viewportで観戦操作とログが利用可能。実機未確認の場合は実機確認済みと扱わない。
- 複数Seedで施設停止、Checkpoint喪失、資源不足死、住宅利用、最終波への到達と処理状況を記録する。1戦の勝敗だけで調整を断定しない。
