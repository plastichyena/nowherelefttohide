# 1. 文書の目的

本書は、ゾンビウイルス流行下の架空のアメリカ風州を舞台とする、スマートフォンおよびPCブラウザ向けターン制ヘックスストラテジーのPoC実装要件を定義する。

最優先の検証対象は次のゲーム体験である。

> 限られた人口・部隊・物資で領土と生産力を拡大したい一方、人口増加・感染・防衛範囲拡大によってリスクも増える。その状況で、予告されるHordeを見据えて「何を確保し、何を守り、何を諦めるか」を考えることが面白いか。

PoCでは完成品相当のコンテンツ量や演出を目指さず、情報を読み取り、判断し、結果を確認できる最小プレイアブル版を完成させる。

## 1.1 デザイン上の狙い

本作は、「大戦略」系のヘックス上で部隊を移動・配置する戦術判断と、「They Are Billions」系の人口・生産基盤を拡大するほど防衛リスクも増えるHorde防衛体験を、スマートフォンで扱えるターン制ゲームへ再構成する。

再現したい体験は次の3点である。

1. 部隊の位置・射程・再配置によって戦線を構築する
2. 人口と施設を増やすほど経済は強くなるが、感染時の損失も増える
3. 予告されたHordeに対し、拡張を続けるか防衛へ切り替えるか判断する

リアルタイム操作、大量個体の直接描画、複雑な基地建築を再現することは目的としない。それらが生む圧力と意思決定を、ターン・ヘックス・施設管理へ抽象化する。

本節に記載する既存作品名は、実装担当者間で目標とする体験を共有するための内部的な参照である。公開時のゲーム名、宣伝文、画面表示では、特定作品の派生・公式関連作と誤認される表現を使用しない。

## 1.2 実装に迷ったときの優先指標

仕様に明記されていない判断や複数案の選択で迷った場合は、次の順序で評価する。

1. **現在の安全と将来の生産力のトレードオフを生むか**

   単に有利なだけの選択肢より、拡張・人口増加・戦力配備に代償や将来リスクが伴う案を優先する。

2. **位置、射程、Horde予告を使った計画を生むか**

   偶発的な結果だけでなく、盤面を読み、数ターン先を考え、再配置する余地がある案を優先する。

3. **スマートフォン縦画面で理解・操作できるか**

   細かな個別管理や操作回数を増やす案より、少ない操作で結果と理由を読み取れる案を優先する。

上記が競合する場合は、写実性やシミュレーション量より意思決定の明瞭さを、演出よりゲーム状態の可読性を、UI上の便宜的な直接変更よりGameActionとGameEngineによる一貫した状態遷移を優先する。

# 3. ゲーム概要

## 3.1 タイトル

- 日本語: **逃げ場なし**
- 英語: **Nowhere Left to Hide**

## 3.2 ジャンルとプレイヤーの立場

- ターン制ストラテジー
- ヘックス制大戦略
- 都市・資源管理
- ゾンビサバイバル

プレイヤーは州知事として、州都、都市、住民、警察、州兵、インフラ、検問所を管理する。

## 3.3 ゲーム長と勝敗

- デフォルト最大ターン: 30
- 最大ターンは新規ゲーム用Configで変更可能
- 最終ターンの既存ゾンビ行動・感染処理まで生存すると勝利
- 最終ターンに次回Hordeが予定されていても、新しいHordeは生成しない

以下のいずれかが成立した瞬間に即敗北とし、以後の状態遷移を停止する。

1. 州都が陥落する
2. 就業者と無職者の合計が0になる

検問所の待機避難民、審査中避難民、施設内感染者、ユニット人口は、労働者0人敗北の回避には数えない。

# 4. 技術・ライセンス・公開

## 4.1 技術構成

- TypeScript
- Phaser
- Vite
- HTML5 / WebGL / Canvas
- テストランナーは許諾的ライセンスのものを採用する

ゲームCoreはPhaserへ依存させない。Phaserは描画、カメラ、入力、画面遷移に限定する。

```text
UI / Phaser
    ↓ GameAction
GameEngine
    ↓
GameState
    ↓ Read Only
UI / Phaser
```

UIおよびPhaser側からGameStateを直接変更してはならない。

## 4.2 ライセンス方針

- 依存ライブラリは原則としてMIT、Apache-2.0、BSD、ISC等の許諾的ライセンスに限定する
- 素材はCC0、フォントはOFLも許容する
- GPL、AGPL、LGPL系の依存は採用しない
- 外部画像素材は原則使用せず、図形、文字、自作記号で構成する
- `THIRD_PARTY_NOTICES`に依存物の著作権とライセンスを記録する
- PoC本体には当面ライセンスを付与しない

## 4.3 対象ブラウザ

優先して確認する環境:

- iPhone Safari
- Android Chrome
- PC Chrome

## 4.4 GitHub公開

- 公開GitHubリポジトリを使用する
- `main`へのpushを契機にGitHub Actionsでテスト、ビルド、GitHub Pagesデプロイを行う
- 現時点ではGitHub CLIが未認証のため、実装時はローカルGit初期化とWorkflow作成までを最低保証とする
- 公開時までにGitHub認証が利用可能になれば、公開リポジトリ作成、push、Pages設定まで行う

# 5. UI・操作要件

## 5.1 画面方向とレイアウト

- スマートフォン縦向きを基準とする
- 盤面を上部、選択情報と操作パネルを下部へ配置する
- 15×15マップは一画面へ固定表示せず、ドラッグによるパンとピンチズームへ対応する
- PCではマウス操作にも対応する
- 将来の横向き対応を妨げないレスポンシブ構造にする

## 5.2 ビジュアル

- 情報優先の作戦図スタイル
- 色分けしたヘックス
- 単純なユニット記号と施設アイコン
- 所有、感染、停止、選択、合法手、Horde方向を明確に区別
- 専用イラストは必須としない

## 5.3 タイトル画面

以下を表示する。

- ゲームスタート
- ロード
- オプション
- ヘルプ
- 言語切り替え

## 5.4 新規ゲームとオプション

新規ゲーム開始時に使用したConfigをGameStateへコピーして固定する。途中再開したゲームへ、その後のオプション変更を反映してはならない。

開始画面またはオプション画面で変更可能な主要項目:

- Seed
- 最大ターン
- Horde周期
- Horde初期数
- Horde増加数
- Horde予告開始ターン
- 避難民到着間隔の最小・最大
- 避難民到着人数の最小・最大
- 審査枠
- 主要な資源・感染倍率

その他の詳細値はConfigファイルで変更する。

## 5.5 ユニット操作

1. ユニットをタップ
2. 合法な移動先を表示
3. 移動先をタップ
4. 経路、到達地点、最初の迎撃リスクをプレビュー
5. 確認ボタンで移動を実行
6. 移動後に攻撃可能対象を表示
7. 攻撃または待機で行動確定

軍事Actionは確定後に巻き戻さない。労働者配置は、感染制限に反しない範囲でターン終了前まで再調整できる。

## 5.6 ガイドとヘルプ

- 初回起動時に、移動、攻撃、労働者配置、ターン終了を短いガイドで説明する
- ゲーム中に日本語・英語の常設ヘルプを開ける
- ターン終了時に資源不足が予測される場合は警告し、無視して進行する選択も認める

# 6. GameState・GameAction・乱数

## 6.1 GameState

ゲーム進行に必要な状態はJSON化可能にする。

最低限、以下を含む。

- ゲームVersion
- 使用中Configの完全なコピー
- Seedと疑似乱数状態
- 現在ターン、最大ターン
- マップID、タイル、道路、施設
- 所有、確保順、稼働、陥落、内部感染
- 就業者、無職者、施設別労働者
- 5資源と電力Capacity
- ユニット、HP、位置、行動状態、攻撃権
- 検問所、待機人数、審査人数、残り時間、方針
- Hordeの回数、次回方向、残りターン
- 直近イベントと累積統計
- 勝敗状態

## 6.2 GameAction

すべての操作をGameActionとしてGameEngineへ渡す。

最低限:

- Move
- Attack
- Wait
- SuppressInfection（内部処理上のAction。UIでは自動）
- AssignWorkers
- SetCheckpointPolicy
- BuildCheckpoint
- ProduceUnit
- EndTurn
- StartNewGame
- LoadSnapshot

不正なActionはGameStateを変更せず、理由付きエラーを返す。

## 6.3 Seed付き乱数

ゲームルール内で`Math.random()`を直接使用しない。

対象:

- ゾンビAIの同順位選択
- Horde方向
- Horde配置の同距離候補
- 避難民到着間隔と人数
- 避難民感染判定
- 潜伏感染の発生施設
- Configで有効化した初期生存者・感染者抽選

同じVersion、Config、Map、Seed、Action列から同じ結果を得られる構造にする。Replay機能自体は今回対象外とする。

## 6.4 Headless Game Interface

ゲームはPhaser、DOM、描画、音響、ブラウザ入力なしでも、初期化からGame Overまで完全に進行可能にする。

最低限、概念的に以下のインターフェースを提供する。

```ts
interface HeadlessGame {
  reset(seed: number, config: GameConfig): Readonly<GameState>;
  getState(): Readonly<GameState>;
  getLegalActions(): GameAction[];
  step(action: GameAction): StepResult;
  isGameOver(): boolean;
  getResult(): GameResult | null;
}
```

- Test Agentには情報制限を設けず、完全なGameStateを渡す
- Fog of WarやAI向けObservationは介在させない
- 人間UIとTest Agentは同じGameAction、ActionValidator、GameEngineを使用する
- `step`はAction適用結果、発生イベント、エラー、Game Over状態を返す
- Game Over後の`step`は状態を変更せずエラーを返す
- Headless実行のためだけの別ルールや状態変更経路を作らない

`getLegalActions()`は現在状態から実行可能な原子的Actionを返す。労働者配置は、施設と設定可能人数を個別Actionとして表し、複数施設の全組み合わせを一括列挙しない。

## 6.5 Random Test Agent

Random Test Agentはゲーム攻略能力ではなく、GameEngineの破壊テストを目的とする開発・CI専用機能とする。

- 完全なGameStateと`getLegalActions()`を利用可能
- 合法手からSeed付きでActionを選ぶ
- 移動、攻撃、待機、労働者配置、編成、検問所建設、方針変更、ターン終了を対象にする
- 同一ターン内の再配置ループ等を避けるため、1ターンの最大Action数をConfigで制限する
- 上限到達時は、合法なら`EndTurn`を強制選択する
- 各Action後と各ターン後に不変条件を検査する
- Game Overまで進行するか、明示した安全上限へ到達した時点で失敗として報告する
- 失敗時はVersion、Config、Map ID、Seed、Action列、エラー、不一致直前のGameStateを保存する

Test Agentの判断理由表示、勝利を目指す戦略、Persona、観戦UIは実装しない。

# 8. ユニット・行動・戦闘

## 8.1 初期性能

| ユニット | HP | Attack | 移動 | 射程 | 人口 |
|---|---:|---:|---:|---:|---:|
| 警察 | 25 | 5 | 5 | 1 | 5 |
| 州兵 | 50 | 10 | 5 | 2 | 10 |
| ゾンビ | 10 | 5 | 3 | 1 | — |

すべてConfig化する。

## 8.2 1ターンの行動

プレイヤーターン中、各ユニットは1回アクティベートできる。

選択肢:

- 移動のみ
- 攻撃のみ
- 移動後に攻撃
- 移動後またはその場で待機

攻撃後は移動できない。攻撃または待機で行動を確定する。移動後に攻撃しない場合は待機を選ぶ。

内政操作はターン終了まで任意回行える。ただし資源、人口、感染等の合法条件を満たす必要がある。

## 8.3 1タイル1駒

- 敵味方を問わず、1タイルに存在できるユニット駒は1つ
- 施設はタイル属性であり、駒とは別に存在する

## 8.4 通常戦闘

1. 攻撃側が先にAttack値分のダメージを与える
2. 防御側が生存している場合のみ反撃可能
3. 防御側の射程内であり、攻撃権が残っている場合のみ反撃
4. 反撃は防御側の攻撃権を消費
5. 撃破されたユニットは反撃できない
6. HPは0未満にしない
7. 死亡ユニットは盤面と合法手から除外

## 8.5 迎撃

- 移動経路の各ヘックスで判定
- 敵射程へ初めて入った地点で迎撃
- 迎撃されたユニットはその地点で移動終了
- 生存していれば、その後に攻撃または待機を選択可能
- 迎撃側は攻撃権を消費
- プレイヤーとゾンビの双方へ同じルールを適用

## 8.6 自然回復

警察・州兵は、前回の自ターンから次回自ターン開始までに以下をすべて満たした場合、最大HPの10%を回復する。

- 移動していない
- 通常攻撃していない
- 迎撃していない
- 感染鎮圧していない

端数処理はConfigで定義し、初期実装では切り上げとする。ゾンビは回復しない。

## 8.7 追加編成

- 所有都市で警察・州兵を予約生産
- 次の自ターン開始時に完成
- 完成ターンから行動可能
- 都市タイルが埋まっている場合は最寄りの空きヘックスへ配置
- 同距離候補はSeed付き乱数で決定
- 必要人口は無職者からのみ支払う
- 必要人数の無職者がいなければ編成不可
- 就業者を自動徴用しない

初期コスト:

- 警察: 人口5、民需品10、軍需品10
- 州兵: 人口10、民需品20、軍需品25

# 9. 人口と労働者配置

## 9.1 管理人口

- 就業者
- 無職者
- 警察人口
- 州兵人口
- 検問所の待機・審査中避難民
- 施設内感染者

資源を消費する総人口は次のみ。

- 就業者
- 無職者
- 警察人口
- 州兵人口

待機・審査中避難民と感染者はプレイヤー資源を消費しない。

## 9.2 配置

- 労働者は全体プールから所有施設へ即時配置
- 非感染施設間では距離を無視して、ターン終了前まで回数制限なく再配置可能
- 感染者が1人以上いる施設では、感染者が0になるまで労働者の追加と撤収を禁止
- 施設上限を超える配置は不可

## 9.3 無人施設

- 安全な所有施設から全労働者を外しても陥落しない
- 所有・無人・非稼働施設として残る
- 感染またはゾンビ襲撃によって人口が0になった場合のみ陥落する

# 10. 資源・生産・不足

## 10.1 5資源

- 食料: 備蓄
- 民需品: 備蓄。医薬品、衛生用品等を含む
- 軍需品: 備蓄
- 燃料: 備蓄
- 電力: 備蓄ではなくCapacity

## 10.2 初期生産式

| 施設 | 労働者1人あたりの入力 | 出力 |
|---|---|---|
| 農場 | 燃料1 | 食料5 |
| 民需工場 | 燃料1 | 民需品5 |
| 都市 | なし | 民需品1 |
| 軍需工場 | 燃料1＋民需品1 | 軍需品2 |
| 製油所 | なし | 燃料5 |
| 発電所 | なし | 電力Capacity 5 |

すべてConfig化する。

## 10.3 電力

- 労働者が1人以上配置された稼働施設は、施設単位で電力Capacity 5を要求
- 都市も電力Capacity 5を要求
- 発電所と検問所は電力を要求しない
- Capacity不足時は、確保時期が古い施設から優先
- Capacityを満たせない施設は施設単位で停止
- 電力は備蓄せず、そのターンの発電所労働者から即時算出

## 10.4 ターン開始時備蓄の原則

そのターンの消費と生産入力には、ターン開始時点の備蓄だけを使用する。

- 今回生産した燃料は同じターンの農場・工場で使えない
- 今回生産した民需品は同じターンの軍需工場で使えない
- 今回生産した食料・民需品・軍需品は同じターンの人口・軍隊維持に使えない
- 全消費と入力処理後に、今回の生産物を備蓄へ加える

## 10.5 消費

- 食料: 資源消費対象の総人口と同数
- 民需品: 資源消費対象の総人口と同数
- 軍需品: 警察人口＋州兵人口と同数

民需品は人口消費を軍需工場入力より優先する。

## 10.6 燃料不足と部分稼働

- ターン終了前に、現在の備蓄で予定消費を満たせるか表示
- 労働者配置変更により備蓄内へ収まれば警告を消す
- 警告を無視してターン終了可能
- 燃料不足時は施設単位で全停止せず、労働者単位で部分稼働
- 確保時期が古い施設から燃料を配分
- 配分できた人数分だけ生産
- 余った燃料は備蓄に残す

## 10.7 食料・民需品不足

- 不足1につき労働者1人を失う
- 無職者から先に減らす
- 次に、後から配置された就業者から決定的な順序で減らす
- 食料不足と民需品不足は別々に計算し、損失を合算
- 例: 食料10不足、民需品10不足なら合計20人減少
- 労働者総数が0になった瞬間に即敗北

## 10.8 軍需品不足

- 必要量に1でも不足すると、全州兵の射程を2から1へ低下
- 警察には影響しない
- 必要量を満たした次の供給判定で射程2へ戻る
- 供給状態はGameStateへ明示的に保存する

# 11. 感染・陥落・復旧

## 11.1 施設の感染状態

各施設は最低限、以下を持つ。

```text
workerCapacity
workers
infected
status
```

## 11.2 ゾンビによる感染

ゾンビが施設タイル上でゾンビターンを終了した場合:

```text
newInfected = min(zombieAttack, workers)
workers -= newInfected
infected += newInfected
```

検問所では`workers`の代わりに`waiting + screening`を使用する。

## 11.3 内部感染

ゾンビが去った後も、感染者が残る限りターンごとに増加する。

```text
spread = min(infected, workers)
workers -= spread
infected += spread
```

検問所では待機・審査中避難民を同じ式の対象とする。人数減算順は決定的にし、初期実装では待機人数を先、審査中人数を後とする。

## 11.4 感染鎮圧

- 警察または州兵が感染施設へ駐留すると内部感染の加算を停止
- 通常攻撃・迎撃をしていなければターン終了時に自動鎮圧
- 移動後の鎮圧は可能
- 鎮圧は攻撃権を消費

警察:

```text
infected -= Police Attack
```

州兵:

```text
infected -= Military Attack
workers -= ceil(Military Attack * 0.5)
```

各値は0未満にしない。検問所では州兵の民間人被害を待機・審査中人数から減らす。

## 11.5 施設陥落

感染またはゾンビ襲撃によって対象人口が0になった場合のみ陥落する。

- 通常施設は荒廃感染施設へ変化
- 検問所は荒廃検問所となり、新しい避難民が来なくなる
- 安全な施設を自主的に無人化した場合は陥落しない
- 陥落時の内部感染者は、現在値と`workerCapacityの50%`の大きい方を基準とする
- 検問所では審査枠をCapacity相当として扱う
- 50%と端数処理はConfig化し、初期実装は切り上げ

## 11.6 陥落時ゾンビ生成

- 都市、生産施設、検問所のいずれも、陥落時にゾンビ駒を2体生成
- 内部感染者数に関係なく2体固定
- 生成数はConfig化
- 隣接空きヘックスを優先
- 空きが足りなければ距離2、距離3と探索範囲を広げ、必ず最寄りの空きヘックスへ配置
- 同距離候補はSeed付き乱数で決定
- 州都陥落時もイベント処理後に即敗北

## 11.7 復旧

- 警察または州兵が駐留し、鎮圧で内部感染者を0にすると復旧
- 復旧した通常施設の労働者は0
- 復旧した検問所は所有状態と設定方針を維持し、避難民受け入れを再開

# 12. 検問所・避難民

## 12.1 建設

- 道路属性を持つヘックスにのみ建設可能
- 警察がその道路ヘックス上にいること
- 警察のそのターンの行動権を消費
- 民需品25を消費
- 即時完成
- 州兵は建設不可
- 東西南北の各方面に最大1か所、合計4か所
- 方面判定は固定マップConfigで定義

## 12.2 到着

- 稼働中の検問所ごとに独立して避難民が到着
- デフォルト到着間隔: 2～4ターン
- デフォルト到着人数: 5～10人
- Seed付き乱数で決定
- 間隔と人数の最小・最大をConfig化
- 最小値と最大値を同じにすれば固定方式を再現可能

## 12.3 人数集計と審査枠

詳細な集団FIFOは持たず、検問所ごとに以下を保持する。

```text
waiting
screening
remainingTurns
screeningPolicy
currentPolicy
```

- デフォルト審査枠: 10人
- 審査枠はConfig化
- 枠が空けば`min(waiting, screeningCapacity)`人を審査へ移す
- 審査中の人数は開始時の方針で最後まで処理
- 方針変更は次の審査枠から適用
- 素通りも1ターンあたり審査枠人数を上限として即時処理

## 12.4 審査方針

### 素通り

- 審査時間: 即時
- 労働者化率: 100%
- 感染発生率: 50%
- 感染発生時人数: 受入人数の50%、端数切り上げ

### 通常

- 審査時間: 2ターン
- 労働者化率: 75%
- 感染発生率: 25%
- 感染発生時人数: 受入人数の25%、端数切り上げ

### 厳格

- 審査時間: 5ターン
- 労働者化率: 50%
- 感染発生率: 0%
- 感染発生人数: 0

労働者化人数の割合計算は初期実装では切り捨てとし、最低受入人数等はConfigで調整可能にする。受け入れられなかった人数は管理対象外となる。

## 12.5 潜伏感染の発生先

- 審査完了時にSeed付き乱数で感染発生判定
- 発生した場合、検問所を除く、労働者が1人以上いる所有施設から発生先をランダム選択
- 無人施設は候補外
- 対象施設の労働者を感染者へ変換
- 対象労働者が不足する場合は`min`で制限
- 候補施設がない場合は受け入れ確定を保留し、候補が生じた時点で判定結果を解決する

この処理は「審査を通過した避難民が州内へ移動した後に発症した」ことを表す。

## 12.6 検問所襲撃

- ゾンビが検問所タイル上でゾンビターンを終了した場合に成立
- 単に攻撃を受けた、または隣接しただけでは避難民感染は発生しない
- `waiting + screening`を通常施設の労働者と同様に感染処理
- 検問所専用の追加ゾンビ生成ルールは設けない
- 感染処理によって待機・審査中人数が0になった場合は陥落
- 単なる到着待ちで0人の場合は陥落しない

# 13. ゾンビAI

優先順位:

1. 最も近い人間タイル
2. 同距離なら対象人口が最も多いタイル
3. 同数ならSeed付き乱数

人口評価に含むもの:

- 施設労働者
- 警察人口
- 州兵人口
- 検問所の待機避難民
- 検問所の審査中避難民

経路探索は移動コスト1、1タイル1駒、迎撃を考慮する。確認可能な全人間タイルを対象とし、Fog of Warは実装しない。

# 14. Horde

## 14.1 初期値

- 周期: 5ターンごと
- 初回: 2駒
- 以降: 毎回2駒ずつ増加
- 例: 2、4、6、8、10、12
- 方向: 東西南北からSeed付き乱数
- 規模はプレイヤーへ非公開
- 方向と残りターンは公開

周期、初回数、増加数はConfig化する。

## 14.2 予告

- ゲーム開始時から次回Hordeの方向と残りターンを表示
- Horde生成直後に次の方向を決め、次回予告へ切り替える
- 予告開始タイミングはConfig化可能

## 14.3 配置

- 予告方向の主要道路入口を中心に配置
- 空いている隣接外周ヘックスへ分散
- 足りなければ近い空き外周ヘックスへ探索範囲を広げる
- 同順位候補はSeed付き乱数
- Turn 5 HordeはTurn 5終了時に生成され、次回ゾンビ行動フェーズから活動
- 最終ターンには新しいHordeを生成しない

# 15. ターン処理

```text
PLAYER TURN START
  自然回復
  攻撃権・行動権回復
  予約ユニット完成・配置
  即時敗北条件確認
        ↓
PLAYER ACTION
  ユニット選択
  移動 / 迎撃 / 攻撃 / 待機 / 施設確保
        ↓
DOMESTIC ACTION
  労働者配置
  検問所方針
  検問所建設
  ユニット編成予約
        ↓
END TURN VALIDATION
  資源・電力予測
  不足警告
        ↓
ECONOMY
  ターン開始時備蓄から人口消費
  不足被害と即時敗北確認
  電力Capacity決定
  ターン開始時備蓄から生産入力配分
  部分稼働
  今回生産物を備蓄へ追加
  次期間の軍需供給状態更新
        ↓
REFUGEES
  到着
  審査進行
  労働者化
  潜伏感染判定
  即時敗北条件確認
        ↓
INTERNAL INFECTION / SUPPRESSION
  駐留ユニットの鎮圧
  鎮圧されていない施設の内部感染
  陥落・復旧・即時敗北確認
        ↓
ZOMBIE TURN
  AI / 移動 / 迎撃 / 戦闘
        ↓
ZOMBIE INFECTION
  タイル上の施設・検問所を感染
  陥落・即時敗北確認
        ↓
HORDE SPAWN
  最終ターンでなければ予定Horde生成
        ↓
WIN CHECK
        ↓
NEXT TURN
```

各サブフェーズ内の順序は決定的にする。即時敗北が成立した場合は残り処理を行わない。

# 16. 保存・復元

## 16.1 ローカル自動保存

- 各確定Actionまたはターン終了時にブラウザのローカル領域へ保存
- タイトル画面に「続きから」を表示
- 保存失敗時は明示的に通知

- Game Version、Config、Map ID、Seed、完全なGameStateを含む
- 圧縮後にBase64URL等の安全な文字列へ変換
- チェックサムを付与
- コピー・貼り付けで復元可能
- コードが数千文字になることを許容

## 16.3 JSONファイル

- セーブコードと同一内容をJSONファイルとして書き出し・読み込み可能
- スマートフォンブラウザでも可能な標準Web APIを使用

## 16.4 安全性

- Version不一致、破損、不正Config、不変条件違反を検出
- 検証に失敗したデータは現在状態へ適用しない
- ロードしたゲームは保存時のConfigを使用し、現在のオプション値を上書き適用しない

# 18. 自動テスト

## 18.1 主要ルール

- 合法・不正移動
- 経路上迎撃と移動停止
- 先制攻撃、反撃条件、撃破時反撃不可
- 攻撃後移動不可
- 自然回復条件
- 施設確保
- 労働者配置制限
- 5資源の生産、前ターン備蓄原則、部分稼働
- 電力Capacityと施設停止
- 食料・民需品不足の合算被害
- 軍需品不足の全州兵射程低下
- 避難民審査枠、方針固定、受入率、感染率
- ゾンビ感染、内部感染、鎮圧、陥落、復旧
- Horde予告、増加、配置、最終ターンスキップ
- 勝利・即時敗北
- 保存・復元の往復一致

## 18.2 不変条件

常に以下を満たす。

```text
HP >= 0
Workers >= 0
Unemployed >= 0
Infected >= 0
WaitingRefugees >= 0
ScreeningRefugees >= 0
Resources >= 0
UnitPopulation >= 0
```

加えて:

- 1タイル1駒
- 死亡ユニットは行動不可
- 行動済みユニットは再行動不可
- Game Over後に状態遷移しない
- 施設上限を超えて労働者を配置しない
- 感染施設へ労働者を追加・撤収しない
- 同一SeedとAction列で乱数結果が一致する

## 18.3 Random Test Agent Test

- Headless Game Interfaceだけを使用し、UIを起動せずゲームを進行する
- 各Action後と各ターン後に18.2の不変条件を検査する
- CIでは異なるSeedで最低100ゲームを実行する
- ローカルではConfig指定により1,000ゲーム以上を実行可能にする
- 1ゲームのAction数とターン数に安全上限を設け、無限ループを失敗として検出する
- 同じ失敗SeedとAction列を再実行し、同じ失敗状態が再現することを確認可能にする
- Game Overまで完走したこと自体を攻略AIの性能評価として扱わない

Replay UI、Rule Based Agent、バランス統計を生成する大規模Batch Simulationは後続フェーズとする。
